# Flutter 사용자 제재 실행 계획

이 문서는 `docs/usersanction/USER_SANCTION_POLICY.md`를 실제 Flutter 앱 구현 수준으로 내린 실행 계획서다.

전제:

- 관리자 웹 React에서 사용자 제재 생성/해제 기능은 이미 구현되어 있다.
- 백엔드는 로그인, 토큰 갱신, 내 정보 조회 응답에 `accountStatus`, `suspensionUntil`, `sanctionReasonSummary`를 내려준다.
- Flutter 앱의 목표는 제재 상태를 일관되게 반영하고, 사용자 혼란 없이 제한 모드와 정지 상태를 처리하는 것이다.

---

## 1. 문제 정의

현재 사용자 제재는 관리자 웹에서 집행할 수 있지만, Flutter 앱은 제재 직후 사용자를 어떻게 안내하고 무엇을 막아야 하는지 제품/구현 수준의 실행 계획이 필요하다.

해결해야 하는 문제:

- 사용자가 로그인 직후 제재 상태를 즉시 이해할 수 있어야 한다.
- 일시정지 사용자는 허용 기능만 쓰고, 막힌 기능에서는 일관된 안내를 받아야 한다.
- 무기한 정지 사용자는 세션이 남아 있어도 앱이 빠르게 제한 모드로 수렴해야 한다.
- 앱 내 여러 화면이 서로 다른 정책으로 동작하지 않도록 공통 상태 관리 기준이 필요하다.

## 3. 백엔드 source of truth

### 3.1 상태 응답 필드

Flutter 앱은 아래 응답을 source of truth로 사용한다.

- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `GET /api/v1/users/me`

확인 필드:

- `accountStatus`
- `suspensionUntil`
- `sanctionReasonSummary`

실제 계정 상태 값:

- `ACTIVE`
- `WARNING`
- `SUSPENDED`
- `WITHDRAWN`

주의:

- 관리자 제재 타입 `TEMP_SUSPEND`와 앱이 받는 `accountStatus`는 다르다.
- Flutter 앱은 제재 타입이 아니라 `accountStatus`를 기준으로 동작해야 한다.
- 강한 제재도 앱에서는 별도 계정 상태 추가 없이 장기 `SUSPENDED`로 처리한다.

### 3.2 서버 차단 동작

현재 백엔드 기준:

- `WITHDRAWN`은 로그인과 토큰 갱신 단계에서 차단된다.
- `SUSPENDED`는 로그인/토큰 갱신은 허용되지만, 보안 필터가 제한된 API만 허용한다.
- 무기한 정지도 별도 차단 상태가 아니라 장기 `SUSPENDED`로 동작한다.
- 제한 위반 시 서버는 `403 FORBIDDEN`을 반환한다.

일시정지 상태에서 서버가 허용하는 API:

- `POST /api/v1/auth/logout`
- `POST /api/v1/auth/refresh`
- `GET /api/v1/users/me`
- `PATCH /api/v1/users/me/settings`
- `GET /api/v1/users/blocks`
- `POST /api/v1/users/{id}/block`
- `DELETE /api/v1/users/{id}/block`
- `GET /api/v1/inquiries`
- `POST /api/v1/inquiries`
- `GET /api/v1/inquiries/{id}`
- `GET /api/v1/notices`
- `GET /api/v1/notices/{id}`
- `DELETE /api/v1/auth/withdraw`

서버 메시지:

- 일시정지 제한 위반: `일시정지된 계정은 제한된 기능만 사용할 수 있습니다`
- 탈퇴 차단: `이용이 정지된 계정입니다`

## 4. 사용자 시나리오별 동작

### 4.1 경고 사용자

목표:

- 정상 사용은 유지하되 경고 상태를 인지시킨다.

Flutter 처리:

- 로그인 성공 후 기존 홈으로 진입
- 로그인 최초에 쇼다이얼로그에 경고를 1회 노출
- 마이페이지 경고 배너 노출
- 기능 제한은 하지 않음

### 4.2 일시정지 사용자

목표:

- 로그인은 허용하되, 앱 전체가 제한 모드로 일관되게 동작해야 한다.

Flutter 처리:

- 로그인 성공 시 일반 홈으로 보내지 않고 제한 모드 진입 화면 또는 제한 모드 홈으로 이동
- 세션 저장소에 `accountStatus=SUSPENDED`, `suspensionUntil`, `sanctionReasonSummary`를 보관
- 허용 기능 외 진입 버튼은 숨기거나 disabled 처리
- 딥링크나 직접 경로 진입도 라우트 가드에서 차단
- 금지 액션 실행 시 서버 요청 전에 앱에서 1차 차단
- 서버에서 `403 FORBIDDEN`이 오면 제한 모드 안내로 회수

### 4.3 무기한 정지 사용자

목표:

- 사용자가 강한 제재 상태이지만 문의와 이의제기 경로는 남아 있다는 점을 이해해야 한다.

Flutter 처리:

- 로그인 성공 후에도 일반 홈이 아니라 제한 모드로 진입
- `suspensionUntil`이 매우 먼 미래면 UI 문구는 `무기한 정지`로 변환
- 기존 access token으로 앱을 쓰던 중 서버 `FORBIDDEN`이 오면 제한 모드로 회수
- 허용 액션은 일반 일시정지와 동일하게 문의, 공지, 차단 관리, 알림 설정, 로그아웃으로 유지

## 5. 앱 상태 관리 권장 구조

### 5.1 공통 세션 모델

Flutter 앱은 인증 세션과 별도로 `AccountRestrictionState`를 명시적으로 둔다.

권장 필드:

- `accountStatus`
- `suspensionUntil`
- `sanctionReasonSummary`
- `isRestricted`
- `isSuspended`
- `isLongTermSuspended`
- `lastSyncedAt`

파생 규칙:

- `accountStatus == SUSPENDED`면 `isRestricted = true`
- `suspensionUntil`이 운영 기준보다 매우 먼 미래면 `isLongTermSuspended = true`
- 그 외는 일반 상태

### 5.2 상태 갱신 트리거

아래 시점마다 제재 상태를 갱신한다.

- 로그인 성공 직후
- 토큰 갱신 성공 직후
- 앱 cold start 후 자동 로그인 시
- 앱 foreground 복귀 시 `GET /users/me` 재조회
- 서버 `403 FORBIDDEN` 응답 수신 시 fallback 검사

### 5.3 fallback 규칙

응답 코드와 메시지 기준으로 상태를 보정한다.

- `403` + `일시정지된 계정은 제한된 기능만 사용할 수 있습니다`
  - 현재 세션은 유지
  - 제한 모드로 즉시 전환
- `403` + `이용이 정지된 계정입니다`
  - 세션 정리
  - 탈퇴 또는 비정상 계정 종료 플로우로 이동

## 6. 화면/기능별 구현 범위

### 6.1 로그인/스플래시

해야 할 일:

- 로그인 응답에서 제재 상태를 파싱
- 자동 로그인 성공 시 `GET /users/me` 또는 refresh 응답으로 상태 동기화
- 상태에 따라 초기 라우트를 분기

권장 분기:

- `ACTIVE`, `WARNING`: 일반 홈
- `SUSPENDED`: 제한 모드 홈 또는 제한 안내 화면
- `WITHDRAWN`: 정지 안내 화면

### 6.2 홈/탭 구조

해야 할 일:

- 제한 모드에서는 메인 홈, 생성 CTA(행동 유도 버튼), 참여 CTA를 제거
- 하단 탭 구조를 제한 모드 기준으로 재구성하거나, 일반 탭을 유지하되 접근 시 가드 처리

권장안:

- 지금은 일반 탭 유지 + 라우트 가드/버튼 비활성화
- 별도 제한 모드 전용 탭 리디자인은 다음 단계로 미룸

### 6.3 마이페이지

해야 할 일:

- 제재 배너 추가
- `sanctionReasonSummary`, `suspensionUntil` 노출
- 수정 진입 제거
- 탈퇴 버튼은 유지
- 알림 설정, 차단 목록, 문의, 도움말만 남김

### 6.4 문의/도움말/공지

해야 할 일:

- 제한 모드에서도 접근 유지
- 문의 작성 CTA를 눈에 띄게 유지
- 정지 사유 관련 문의를 쉽게 작성하도록 안내 문구 추가

### 6.5 차단한 사용자 관리

해야 할 일:

- 차단 목록 조회와 차단 해제 유지
- 현재 서버가 `POST /users/{id}/block`도 허용하므로, 차단 추가 허용 여부는 제품 결정 필요

권장안:

- 이번 릴리스는 서버 허용 범위에 맞춰 차단 추가도 유지
- 차단 추가를 막고 싶다면 백엔드 정책과 문서를 먼저 바꾼 뒤 앱 UX를 맞춘다

### 6.6 금지 액션 화면

차단 대상:

- 프로필 수정
- 오픈매트 생성/수정/삭제/참가/참가취소
- 대회 작성/수정/삭제
- 신고 생성
- FCM 토큰 등록/삭제

권장 처리:

- 버튼 숨김이 가능하면 숨김
- 상세 화면에서 이미 진입한 상태면 disabled + 안내 문구
- 서버 요청 직전 마지막으로 restriction guard 체크

## 8. 수용 기준

### 8.1 경고

- `WARNING` 사용자는 로그인과 일반 기능 사용이 가능하다.
- 앱 어딘가에서 경고 상태를 확인할 수 있다.

### 8.2 일시정지

- `SUSPENDED` 사용자는 로그인할 수 있다.
- 앱 시작, 로그인, refresh 이후 제한 모드로 일관되게 진입한다.
- 허용 API와 연결된 화면만 정상 동작한다.
- 금지 액션은 UI와 서버 양쪽에서 차단된다.
- `suspensionUntil`과 `sanctionReasonSummary`가 사용자에게 노출된다.

### 8.3 무기한 정지

- 장기 `SUSPENDED` 사용자도 로그인과 refresh가 가능하다.
- 일반 홈 대신 제한 모드로 이동한다.
- `suspensionUntil`은 화면에 그대로 노출하지 않고 `무기한 정지` 문구로 변환할 수 있다.

### 8.4 예외 처리

- 제재 상태 응답이 누락돼도 앱이 크래시하지 않는다.
- `403 FORBIDDEN` 메시지를 근거로 상태 보정이 가능하다.
- 네트워크 실패와 제재 차단을 구분해서 UX를 보여준다.

## 9. 성공 신호

- 정지 사용자가 일반 홈으로 진입하는 케이스가 없어야 한다.
- 제한 모드 사용자의 금지 액션 API 호출이 급감해야 한다.
- 무기한 정지 상태에서 일반 홈 진입 루프가 없어야 한다.
- CS 문의에서 `왜 어떤 화면은 되고 어떤 화면은 안 되냐` 유형의 혼란이 줄어야 한다.

## 10. 핵심 리스크와 완화

### 10.1 상태 불일치

리스크:

- 로그인 응답, refresh 응답, `GET /users/me` 중 하나만 반영하면 화면 상태가 엇갈릴 수 있다.

완화:

- 세 엔드포인트 모두 같은 세션 갱신 함수를 통과시킨다.

### 10.2 화면별 정책 불일치

리스크:

- 어떤 화면은 버튼을 숨기고 어떤 화면은 서버 403까지 가는 식으로 UX가 흔들릴 수 있다.

완화:

- 공통 restriction guard와 공통 안내 문구를 사용한다.

### 10.3 무기한 정지 상태 오판

리스크:

- 이미 로그인된 사용자가 무기한 정지된 뒤 일반 홈이나 금지 액션을 계속 볼 수 있다.

완화:

- foreground 복귀 시 `GET /users/me` 재조회
- `403 FORBIDDEN` 수신 시 세션 즉시 정리

### 10.4 FCM 토큰 정리 공백

리스크:

- 일시정지/무기한 정지 상태에서 앱이 FCM 토큰을 즉시 정리하지 못할 수 있다.

완화:

- 이번 단계에서는 앱 신규 등록/삭제만 막고, 세션 정리는 로그아웃 기준으로 운영
- 추후 서버 정책으로 강제 토큰 만료가 필요한지 별도 결정

## 11. 미해결 의사결정

결정 필요:

- 제품 책임자

권장안:

- 이번 릴리스는 앱 내 문의 진입을 유지
- 이의제기 전용 플로우는 다음 단계로 미룸

### 11.3 경고 UX 강도

현재 상태:

결정 필요:

- 제품 책임자 + 디자인

권장안:

- 이번 릴리스는 배너만 적용

- `ACTIVE` 사용자가 정상 로그인 후 일반 홈 진입
- `WARNING` 사용자가 정상 로그인 후 경고 배너 확인
- `SUSPENDED` 사용자가 로그인 후 제한 모드 진입
- `SUSPENDED` 사용자가 문의 작성 성공
- `SUSPENDED` 사용자가 공지 상세 조회 성공
- `SUSPENDED` 사용자가 프로필 수정 진입 시 앱 차단
- `SUSPENDED` 사용자가 탈퇴 요청 시 정상 진행
- `SUSPENDED` 사용자가 오픈매트 참가 시 앱 차단 또는 서버 `403` 후 제한 안내
- 일반 사용자로 로그인한 뒤 관리자에서 `TEMP_SUSPEND` 부여 후 앱 foreground 복귀 시 제한 모드 전환
- 일반 사용자로 로그인한 뒤 관리자에서 장기 `TEMP_SUSPEND` 부여 후 앱 foreground 복귀 시 제한 모드 전환
- 장기 `SUSPENDED` 사용자가 로그인 시 제한 모드 진입
