# iOS App Review 비회원 접근 대응 기획

## 1. 배경

2026년 4월 30일 App Store Review에서 Guideline 5.1.1(v) 위반으로 리젝되었다.

Apple의 지적은 앱이 계정 기반이 아닌 기능까지 회원가입 또는 로그인을 요구한다는 것이다. 구체적으로 심사자는 `오픈매트`와 `국내 대회 정보`를 보기 전에 등록/로그인이 필요하다고 판단했다.

현재 백엔드 계약상 오픈매트 목록/상세, 대회 목록/상세, 공지사항 목록/상세 조회는 인증이 불필요하다. 따라서 리젝의 핵심 원인은 서버 API 정책보다는 Flutter 앱의 최초 진입 UX가 비로그인 사용자에게 공개 조회 화면으로 가는 경로를 제공하지 않는 데 있다.

## 2. 사용자 문제

비회원 사용자는 앱을 처음 실행했을 때 로그인 화면만 볼 수 있다. 이 상태에서는 앱의 공개 정보 가치인 오픈매트와 대회 정보를 확인할 수 없고, Apple 심사자도 동일하게 “기능 이용 전 개인정보 제공을 요구한다”고 판단한다.

사용자 관점의 문제는 다음과 같다.

- 앱의 기본 정보 탐색 전에 소셜 로그인을 요구한다.
- 오픈매트와 대회 정보가 계정 기반 기능인지 공개 정보 기능인지 UI에서 구분되지 않는다.
- 계정이 필요한 행위와 필요 없는 조회 행위가 첫 화면에서 분리되어 보이지 않는다.

## 3. 현재 동작 정리

### Flutter

- 앱 시작 시 `StartupView`가 세션 복구를 시도한다.
- 세션 복구 성공 시 `/main`으로 이동한다.
- 세션이 없거나 복구 실패 시 `/login`으로 이동한다.
- 로그인 화면에는 Google, Kakao, Apple 로그인 버튼만 있고 비회원으로 계속하는 진입점이 없다.
- `/main`에 도달하면 오픈매트 목록과 대회 목록 버튼은 로그인 체크 없이 이동 가능하다.
- 오픈매트 신청, 신고, 생성, 수정, 삭제 등 계정 기반 액션은 별도 로그인 요구 다이얼로그 또는 인증 API로 보호된다.

### Spring Backend

- `GET /api/v1/open-mats`, `GET /api/v1/open-mats/{id}`는 `permitAll`.
- `GET /api/v1/tournaments`, `GET /api/v1/tournaments/{id}`는 `permitAll`.
- `GET /api/v1/notices`, `GET /api/v1/notices/{id}`는 `permitAll`.
- 신청, 신고, 작성, 수정, 삭제, 내 목록, 알림, 문의, 마이페이지는 인증 필요.
- 로그인 사용자는 Authorization 헤더를 보내 차단 필터 등 개인화 조회를 받을 수 있고, 비로그인 사용자는 공개 목록을 그대로 조회한다.

## 4. 제품 목표

1. 비회원도 앱 실행 직후 오픈매트와 대회 정보를 자유롭게 조회할 수 있게 한다.
2. 계정 기반 기능은 계속 로그인 후에만 사용할 수 있게 한다.
3. Apple 심사자가 계정 생성 없이 공개 정보 기능을 확인할 수 있게 한다.
4. 기존 로그인 사용자 경험과 인증 API 보안 정책을 불필요하게 흔들지 않는다.

## 5. 권장 방향

### 지금 출시 대응 범위

비회원 모드를 명시적으로 제공한다.

권장 UX는 로그인 화면에 `둘러보기` 또는 `비회원으로 계속하기` 버튼을 추가하고, 이 버튼을 누르면 `/main`으로 진입시키는 것이다. 비회원 상태의 `/main`에서는 공개 조회 기능을 우선 노출한다.

비회원 허용 범위:

- 오픈매트 목록 조회
- 오픈매트 상세 조회
- 대회 목록 조회
- 대회 상세 조회
- 공지사항 목록 조회
- 공지사항 상세 조회
- 도움말/FAQ 조회

로그인 필요 유지 범위:

- 오픈매트 신청/신청 취소
- 오픈매트 생성/수정/삭제/관리
- 대회 생성/수정/삭제
- 오픈매트/대회 신고
- 사용자 차단/차단 해제
- 알림함
- 마이페이지/프로필 수정
- 문의 작성/내 문의 조회
- 내가 신청한 오픈매트/내가 개최한 오픈매트

### 이후 개선 범위

초기 화면을 로그인 중심이 아니라 탐색 중심으로 재구성하는 작업은 별도 개선으로 분리한다. 예를 들어 앱 첫 화면을 공개 홈으로 바꾸고 로그인은 필요한 액션 시점에 요구하는 방식이다.

이번 리젝 대응에서는 변경 범위를 줄이기 위해 기존 로그인 화면에 비회원 진입점을 추가하는 방식이 가장 적절하다.

## 6. 대안 비교

### 대안 A. 로그인 화면에 비회원 진입 버튼 추가

장점:

- 구현 범위가 작다.
- 현재 라우팅과 메인 화면 구조를 크게 바꾸지 않는다.
- Apple 심사 대응 메시지가 명확하다.
- 기존 로그인 사용자 흐름 영향이 작다.

단점:

- 로그인 화면이 여전히 첫 화면이라 공개 탐색 앱처럼 보이는 정도는 제한적이다.
- 비회원 상태의 메인 화면에서 사용자 정보 카드 등 일부 UI 조정이 필요하다.

권장 여부: 이번 리젝 대응의 1순위.

### 대안 B. 앱 최초 진입을 항상 메인 화면으로 변경

장점:

- 공개 정보 앱이라는 인상이 가장 명확하다.
- 로그인은 필요한 기능을 누를 때만 요구하는 구조가 된다.

단점:

- 기존 세션 복구, FCM, 계정 제재 상태 동기화, 마이페이지 진입 흐름을 더 넓게 점검해야 한다.
- 출시 직전 변경 범위가 커진다.

권장 여부: 다음 UX 개편 후보.

### 대안 C. App Review 메모만 보강

장점:

- 개발 변경이 없다.

단점:

- 실제 앱 UI에서 비회원 접근이 막혀 있으므로 재심사 통과 가능성이 낮다.
- Apple 지적의 핵심을 해결하지 못한다.

권장 여부: 단독 대응으로는 부적절.

## 7. 세부 기획

### 7.1 로그인 화면

로그인 화면 하단에 `비회원으로 둘러보기` 액션을 추가한다.

동작:

- 탭 시 세션을 만들지 않는다.
- `/main`으로 이동한다.
- refreshToken, accessToken, userId 등 인증 저장소에 값을 쓰지 않는다.

문구 방향:

- 기본 버튼: `비회원으로 둘러보기`
- 보조 설명: `오픈매트와 대회 정보는 로그인 없이 볼 수 있어요.`

### 7.2 메인 화면

비회원 상태에서는 개인화 영역을 줄이고 공개 탐색을 우선한다.

필수:

- 오픈매트 버튼 노출
- 대회 정보 버튼 노출
- 공지사항 또는 도움말 진입 경로 노출

권장:

- 사용자 정보 카드 대신 로그인 유도 카드 또는 간단한 앱 소개 카드 노출
- “신청, 신고, 작성은 로그인 후 사용할 수 있음” 정도의 짧은 안내

주의:

- 로그인하지 않은 상태에서 `/users/me`, `/open-mats/my`, `/open-mats/my-hosting`, `/notifications` 같은 인증 API를 자동 호출하지 않아야 한다.
- 현재 `MainController`는 비로그인 상태에서 프로필과 내 오픈매트 API 호출을 건너뛰는 로직이 있으므로 큰 구조 변경 없이 대응 가능해 보인다.

### 7.3 공개 목록/상세 화면

비회원도 목록과 상세를 그대로 볼 수 있어야 한다.

오픈매트 상세:

- 정보 조회는 허용한다.
- 신청 버튼을 누르면 로그인 필요 다이얼로그를 표시한다.
- 신고, 차단 등 계정 기반 액션도 로그인 필요 다이얼로그를 표시한다.

대회 상세:

- 대회 정보와 포스터 조회는 허용한다.
- 외부 접수 링크는 대회 정보 조회의 일부이므로 비회원에게도 열 수 있게 유지하는 것이 적절하다.
- 신고, 수정, 삭제는 로그인 필요 또는 권한 없음으로 처리한다.

### 7.4 백엔드

이번 대응에서 백엔드 기능 변경은 원칙적으로 필요하지 않다.

확인할 항목:

- 공개 GET API가 운영 환경에서도 실제로 200을 반환하는지 smoke test를 진행한다.
- 잘못된 Authorization 헤더가 없는 비회원 요청에서 401이 발생하지 않는지 확인한다.
- 공개 조회 API 응답에 이메일, 전화번호 등 계정 개인정보가 포함되지 않는지 점검한다.

필요 시 보강할 테스트:

- `GET /api/v1/tournaments`
- `GET /api/v1/tournaments/{id}`
- `GET /api/v1/open-mats`
- `GET /api/v1/open-mats/{id}`
- `GET /api/v1/notices`
- `GET /api/v1/notices/{id}`

위 API가 토큰 없이 성공해야 한다.

## 8. 수용 기준

### 제품 수용 기준

- 신규 설치 후 로그인하지 않아도 오픈매트 목록에 접근할 수 있다.
- 신규 설치 후 로그인하지 않아도 오픈매트 상세에 접근할 수 있다.
- 신규 설치 후 로그인하지 않아도 대회 목록에 접근할 수 있다.
- 신규 설치 후 로그인하지 않아도 대회 상세에 접근할 수 있다.
- 계정 기반 액션을 누르면 로그인 필요 안내가 뜬다.
- 로그인하지 않아도 공개 정보 탐색 중 앱이 로그인 화면으로 강제 이동하지 않는다.

### App Review 수용 기준

- 심사자가 계정을 만들지 않고도 앱의 오픈매트와 국내 대회 정보를 확인할 수 있다.
- 심사 메모에 “오픈매트/대회/공지 조회는 비회원으로 이용 가능하며, 신청/작성/신고/개인화 기능만 로그인이 필요하다”고 설명할 수 있다.
- 앱 영상 또는 스크린샷으로 비회원 접근 경로를 제시할 수 있다.

### 기술 수용 기준

- 비회원 진입 시 secure storage에 인증 토큰이 생성되지 않는다.
- 비회원 상태에서 공개 목록/상세 API 요청은 Authorization 없이 성공한다.
- 비회원 상태에서 인증 API가 자동으로 호출되어 401 토스트가 뜨지 않는다.
- 기존 로그인 사용자는 앱 시작 시 세션 복구 후 기존처럼 메인 화면으로 진입한다.

## 10. 리스크와 완화

### 리스크 1. 비회원 메인 화면에서 개인화 API가 호출됨

완화:

- `isAuthenticated == false`일 때 내 정보, 내 오픈매트, 알림 API 호출을 하지 않는지 확인한다.
- QA에서 네트워크 로그를 확인한다.

### 리스크 2. 공개 상세에서 계정 기반 버튼이 혼란을 줌

완화:

- 버튼 자체는 유지하되 탭 시 로그인 필요 안내를 명확히 보여준다.
- 신청/신고/작성은 계정 기반 기능이라는 문구를 짧게 제공한다.

### 리스크 3. 백엔드 공개 응답에 개인정보가 포함됨

완화:

- 오픈매트/대회 공개 응답 필드를 점검한다.
- 전화번호, 이메일 등 민감 정보는 공개 응답에서 제외한다.

### 리스크 4. Apple이 여전히 로그인 중심 앱으로 판단함

완화:

- 로그인 화면의 비회원 진입 버튼을 충분히 눈에 띄게 배치한다.
- App Review Notes에 비회원 접근 경로를 명시한다.
- 재제출 스크린샷 또는 테스트 안내에 `비회원으로 둘러보기 -> 오픈매트/대회 정보` 흐름을 적는다.

## 12. 최종 권장안

이번 재심사 대응은 대안 A로 진행한다.

1. 로그인 화면에 `비회원으로 둘러보기`를 추가한다.
2. 비회원 상태에서도 `/main`에 진입할 수 있게 한다.
3. 메인 화면에서 오픈매트/대회/공지 조회를 명확히 제공한다.
4. 신청/작성/신고/개인화 기능은 로그인 필요 안내로 막는다.
5. 백엔드는 현재 공개 조회 정책을 유지하고 운영 smoke test만 수행한다.
