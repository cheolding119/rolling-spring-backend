# 대회 성적 및 메달 기록 기획서

## 1. 문서 목적

- 고객 요청인 “대회 성적이나 메달 개수를 기록하고 싶다”를 롤링 앱의 실제 사용 흐름에 맞는 제품 범위로 구체화한다.
- 마이페이지와 메인 홈 중 적절한 진입 위치, MVP 데이터, 프라이버시, 성공 지표와 후속 기능을 결정할 수 있게 돕는다.
- 이 문서는 제품 기획서다. 구현된 도메인 모델과 API 계약은 [대회 성적 명세](../domain_and_spec/tournament-achievement.md)에서 관리한다. 마이페이지 UI와 운영 배포는 별도 작업이다.

## 2. 요약 및 권장안

**MVP는 마이페이지의 “내 대회 기록”에서 사용자가 직접 대회명, 날짜, 메달과 종목 구분을
입력·수정·삭제하는 개인 기록 기능으로 시작한다.**
메인 홈에는 사용자가 기록을 만들었을 때만 총 메달 수와 최근 성과를 보여주는
작은 요약 카드를 실험한다. 다른 사용자 프로필 노출, 공개 랭킹, 공식 결과 자동 수집은 초기 범위에서 제외한다.

권장 이유:

- 현재 롤링에는 대회 일정/접수 정보와 훈련 기록은 있지만, 개인 대회 결과를 보관하는 도메인은 없다. 과거 대회는 롤링 대회 일정 데이터에 없을 수 있으므로, 기존 `Tournament` 일정에 결과를 강제로 연결하지 않고 대회명을 독립 기록으로 받는 편이 적합하다.
- Smoothcomp는 개인 프로필에 대회 이력과 결과를 노출하지만, 공개 설정을 제공하고 주최자가 결과를 공개한 대회만 이력에 반영한다고 안내한다. 즉, 공개 범위와 결과 출처가 별도 제품 결정이다.
- 공식 결과 연동이나 랭킹은 플랫폼별 결과 공개 여부, 선수 식별, 체급/벨트 구분 및 점수 규칙이 필요하다. 직접 입력 MVP로 사용 빈도와 입력 부담부터 확인하는 것이 안전하다.

## 3. 사용자 문제와 목표

### 3.1 사용자 문제

- 사용자는 대회에 참가한 기록과 입상 이력을 앱 안에 모아두고 싶다.
- 금·은·동 (혹은 순위) 메달 수를 다시 계산하지 않고 한눈에 확인하고 싶다.
- 대회 결과를 체육관 동료나 친구와 공유하고 싶을 수 있지만, 성적을 공개하거나 비교당하는 것은 원치 않을 수 있다.
- 대회 일정 데이터에 없는 과거 대회도 기록할 수 있어야 한다.

### 3.2 제품 목표

- 사용자가 본인의 대회 기록을 쉽게 입력하고 이후 다시 찾아볼 수 있게 한다.
- 금·은·동 메달 집계를 자동 제공해 기록의 누적 가치를 만든다.
- 성적 데이터는 기본적으로 소유자만 볼 수 있게 해 원치 않는 공개와 비교를 방지한다.

### 3.3 비목표

- 대회 운영사의 공식 결과를 크롤링하거나 자동 검증하는 것
- 경기별 승패, 상대 선수, 경기 방식, 점수, 브라켓 전체를 저장하는 것
- 친구 간 순위표, 체육관 랭킹, 전국 랭킹을 제공하는 것
- 메달 기록을 롤링 대회 일정에 반드시 연결하는 것

## 4. 사용자 및 핵심 흐름

### 4.1 주요 사용자

- **대회 참가자:** 대회 기록을 쌓고 본인의 성장 과정을 돌아본다.
- **초보 참가자:** 입상 여부와 무관하게 대회 참가 경험을 기록하고 싶다.
- **공유를 원하는 사용자:** 본인이 선택한 기록만 친구나 프로필 방문자에게 보여주고 싶을 수 있다.

### 4.2 MVP 사용자 흐름

1. 사용자가 마이페이지에서 `내 대회 기록`을 선택한다.
2. 기록이 없으면 금·은·동 메달 집계가 비어 있는 상태와 `첫 대회 기록 추가` 버튼을 본다.
3. 대회명과 개최일을 입력하고, 메달을 획득했다면 금·은·동 중 하나를 선택한다. 입상하지 않은 참가 기록도 남길 수 있도록 `참가`를 제공한다.
4. Gi/No-Gi, 벨트, 연령부, 체급 및 체급전/오픈급을 각각 입력한다. 모르는 항목은 비워둘 수 있다.
5. 저장 후 목록과 메달 집계가 갱신된다. 잘못 입력한 기록은 수정 또는 삭제할 수 있다.

## 5. 화면 배치 권장

### 5.1 마이페이지: MVP의 기본 위치

- `내 대회 기록` 진입 항목과 기록 수/메달 요약을 둔다.
- 상세 화면 상단에 금·은·동 합계, 아래에 대회별 기록을 최신순으로 표시한다.
- 기록 추가/수정/삭제와 빈 상태를 이 화면에서 제공한다.
- 기록이 없어도 대회 기록 기능의 가치와 입력 방법을 안내한다.

마이페이지를 먼저 권장하는 이유는 기록의 소유권과 편집 권한이 명확하고, 기존 마이페이지가 계정 기반 개인 기능의 진입점이기 때문이다.

### 5.2 메인 홈: 선택적 요약 진입

- MVP에서 별도 기록 목록을 홈에 중복 구현하지 않는다.
- 사용자가 기록을 1건 이상 저장한 경우, 홈에 `내 메달 2금 · 1은 · 3동`과 최근 기록 1건을 보여주는 작은 카드를 후속 실험한다.
- 기록이 없는 사용자에게는 홈 공간을 차지하지 않도록 기본적으로 카드를 숨기거나, 한 번만 기록 추가 안내를 노출한다.
- 메인 홈이 공개 피드/다른 사용자 콘텐츠를 의미한다면, 초기에는 타인의 성적을 표시하지 않는다.

### 5.3 공개 프로필

- MVP에는 포함하지 않는다.
- 후속 공개를 추진할 경우 사용자가 명시적으로 켜는 공개 설정과 기록별 공개 여부를 먼저 결정한다. 기본 공개로 설정하지 않는다.

## 6. MVP 입력 필드

| 필드 | 필수 여부 | 설명 |
| --- | --- | --- |
| 대회명 | 필수 | 과거·외부 대회도 입력 가능하도록 자유 입력 |
| 개최일 | 필수 | 목록 정렬 및 연도별 회고에 사용 |
| 결과 | 필수 | `GOLD`, `SILVER`, `BRONZE`, `PARTICIPATION` 중 하나 |
| Gi/No-Gi | 선택 | `GI`, `NO_GI` 중 선택 |
| 벨트 | 선택 | 대회 당시의 벨트. 현재 프로필 벨트와 독립 |
| 연령부 | 선택 | 대회 표기 기준. 예: `Adult`, `Master 1` |
| 체급/부문 | 선택 | 체급전·오픈급 구분과 체급 표기. 예: `-76kg` |
| 주최사·결과 링크 | 선택 | 같은 이름의 대회 식별 및 결과 재확인에 사용 |
| 메모 | 선택 | 짧은 개인 메모. 초기 글자 수 제한 필요 |

설계 원칙:

- 메달 수는 사용자가 저장한 메달 기록 수를 합산한다. 참가 기록은 메달 수에 포함하지 않는다.
- 한 대회에서 Gi와 No-Gi 등 여러 부문에 출전해 메달을 여러 개 얻을 수 있으므로, 대회 단위가 아니라 **입상 부문별 기록**으로 저장한다.
- 대회명과 날짜가 같은 기록을 무조건 막지 않는다. 동일 대회 다중 부문 입상을 허용하고, 저장 전 유사 기록을 보여 중복 입력을 확인하게 한다.
- 대회 참가 건수와 메달 수는 구분한다. 동일 대회를 안정적으로 식별할 수 없는 MVP에서는 `기록 건수`를 표시하고, 고유 대회 참가 수 집계는 후속 검증 대상으로 둔다.
- `OTHER` 같은 자유 성적 값은 입력 일관성과 집계를 흐리므로 MVP에서는 받지 않는다. 사용자의 비입상 참가를 위해 `PARTICIPATION`을 제공한다.
- 포스터 이미지/증빙 업로드는 저장·검토·신고 비용이 추가되므로 MVP에서 제외한다.

## 7. 데이터와 기존 도메인 고려사항

- 기존 `Tournament`는 공개 대회 일정, 개최일, 장소, 접수 링크를 나타낸다. 개인 성적은 사용자 소유의 별도 데이터로 모델링하는 것을 권장한다.
- 과거 대회, 외부 대회 또는 롤링에 수집되지 않은 대회도 입력할 수 있어야 하므로 대회 일정 `tournamentId` 연결은 선택 사항이거나 MVP에서는 사용하지 않는다.
- 각 성적 기록에는 사용자 ID와 생성/수정 시각이 필요하다. 사용자 탈퇴 시 연관 기록의 삭제/익명화 정책은 기존 계정 삭제 정책과 함께 정한다.
- 초기 조회 범위는 본인 기록만으로 제한한다. 공개 범위를 후속 추가할 경우 권한 검사를 API와 서비스에서 모두 수행한다.
- 메달 집계 값은 기록을 source of truth로 하여 계산하거나 안전하게 재계산 가능하게 설계한다. 별도 집계 컬럼을 source of truth로 두지 않는다.

## 9. 성공 지표

초기 4~8주 동안 기능 노출 사용자 대비 행동을 측정하고, 사용자 수가 작으면 정량 지표와 인터뷰를 함께 본다.

- **활성화율:** 마이페이지에서 대회 기록 화면에 진입한 사용자 중 첫 기록 저장을 완료한 비율
- **기록 완성도:** 대회명, 개최일, 결과 입력을 완료한 기록 비율 및 선택 부문 필드 입력률
- **반복 사용:** 첫 기록 저장 후 30일 안에 추가 기록을 1건 이상 저장한 사용자 비율
- **유지 사용:** 대회 기록 화면을 2회 이상 조회하는 사용자 비율
- **오류/불만 신호:** 기록 수정·삭제 실패율, 잘못된 메달 집계 신고/문의 건수

초기 목표치는 현재 사용자 규모와 기준선이 없어 임의로 고정하지 않는다. 출시 전 2주 기준선을 잡고, 첫 기록 전환율과 기록 입력 이탈 지점을 바탕으로 제품 책임자가 목표치를 합의한다.

## 10. 수용 기준

- 로그인 사용자는 마이페이지에서 본인 대회 기록 목록과 금·은·동 집계를 확인할 수 있다.
- 기록이 없는 경우 빈 상태와 첫 기록 추가 진입이 제공된다.
- 사용자는 대회명, 개최일, 결과를 입력해 기록을 생성·수정·삭제할 수 있고, Gi/No-Gi·벨트·연령부·체급·오픈급 여부를 각각 기록할 수 있다.
- 결과는 금·은·동 또는 참가로 저장되고, 메달 합계는 금·은·동만 정확히 집계한다.
- 한 대회에서 여러 부문을 기록할 수 있고, 유사 기록은 저장 전에 중복 확인을 돕는다.
- 본인 외 사용자의 직접 조회 요청은 인증/권한 정책에 따라 거부되며, MVP에는 공개 프로필/공개 API가 없다.
- 저장 실패, 네트워크 오류, 삭제 확인 및 빈 목록 상태를 사용자가 이해할 수 있는 UI로 처리한다.
- 메달 집계 결과와 해당 기록 목록을 하나의 source of truth에서 일관되게 갱신한다.

## 11. 핵심 리스크와 완화

| 리스크 | 영향 | 완화 |
| --- | --- | --- |
| 사용자가 성적을 직접 입력해 사실과 다를 수 있음 | 공개 시 신뢰 문제와 분쟁 발생 | MVP는 비공개 개인 기록으로 한정하고 공식 인증/랭킹에 사용하지 않는다. |
| 대회명 자유 입력으로 중복·표기 차이가 발생 | 집계/검색 혼란 | 대회명 자동완성은 후순위로 두고, 유사 기록 확인과 원문 보존을 먼저 제공한다. |
| 한 대회의 여러 부문 입상으로 집계 해석이 달라짐 | 대회 수와 메달 수 혼동 | `기록 건수`와 `메달 수`를 구분하고, 메달 집계는 부문별 기록 수로 정의한다. |
| 성적 노출이 비교/부담으로 이어짐 | 입력 저하 및 이탈 | 소유자 전용을 기본값으로 하고 공개/순위 기능은 별도 사용자 조사 전 보류한다. |
| 직접 입력 과정이 길어짐 | 첫 기록 저장률 저하 | 필수 입력을 대회명·개최일·결과로 제한하고, 나머지는 접을 수 있는 선택 항목으로 배치한다. |
| 공식 결과 플랫폼별 데이터 형식/공개 정책이 다름 | 연동 유지보수 및 오매칭 | MVP에서는 자동 수집하지 않고, 외부 사례를 데이터 연동의 보장으로 해석하지 않는다. |

## 12. 미해결 결정사항

| 결정 | 권장 기본값 | 결정 주체 |
| --- | --- | --- |
| 메인 홈 카드의 MVP 포함 여부 | 마이페이지를 먼저 출시하고 홈 카드는 사용 데이터 확인 후 추가 | 제품 책임자 |
| 기록 공개 범위 | 본인 전용 | 제품 책임자 및 개인정보/운영 담당 |
| `PARTICIPATION` 기록을 제공할지 | 제공. 입상하지 않은 참가 경험도 기록 수요가 있을 수 있음 | 제품 책임자 |
| 종목 구분 필드 방식 | Gi/No-Gi와 벨트는 enum으로 분리하고, 운영사별로 다른 연령부/체급 명칭은 각각 별도 텍스트로 보존 | 제품 책임자와 엔지니어링 |
| 성적 인증 또는 증빙 | MVP 제외, 필요성 확인 후 검토 | 제품 책임자 및 운영 담당 |
| 과거 연도 기록 허용 범위 | 제한 없이 허용하되 날짜는 미래 불가 | 제품 책임자 |

## 13. 조사 및 내부 근거

### 외부 제품 사례

- [Smoothcomp Athlete Profile](https://support.smoothcomp.com/article/398-athlete-profile): 선수 프로필에서 대회 이력, 출전 부문, 경기 결과를 볼 수 있고, 프로필은 공개/비공개로 선택할 수 있다. 대회 결과는 주최자가 공개한 경우에만 프로필에 표시된다고 설명한다. 이는 성적 기록 기능에서 공개 범위와 결과 출처를 분리해야 한다는 근거로 활용했다.
- [Smoothcomp Results and Top Lists](https://support.smoothcomp.com/article/387-how-to-view-results): 대회 결과 화면에서 부문별 메달리스트와 전체 결과를 확인하는 구조를 안내한다. 롤링 MVP의 개인 입력 기록과 공식 대회 결과 페이지는 별개 기능으로 다룬다.
- [IBJJF Athlete Ranking Information](https://ibjjf.com/athlete-ranking-info): 공식 랭킹은 입상 순위, 대회 등급, 시즌별 점수 규칙을 결합하고 이전 시즌 점수가 이월되지 않는다고 안내한다. 따라서 단순 메달 합계만으로 공식 경쟁 랭킹을 만들 수 없으며, MVP에서 랭킹을 제외하는 근거다.
- [IBJJF Athlete Results example](https://ibjjf.com/athletes/jo-pantoja): 선수별 대회 결과 페이지 사례. 공식 대회 플랫폼의 식별된 선수 결과는 사용자 자가 입력 이력과 데이터 출처/신뢰 수준이 다르다.

### 롤링 내부 현황

- 사용자 정보 응답은 닉네임, 소속, 벨트 및 그랄 수 등을 제공하지만 대회 성적 컬렉션은 포함하지 않는다: [UserResponse.java](../../src/main/java/com/rolling/api/domain/user/dto/UserResponse.java), [User.java](../../src/main/java/com/rolling/api/domain/user/entity/User.java).
- 대회 도메인은 공개 대회 일정/조회와 운영 기능을 다루며 성적 엔티티는 없다: [tournament.md](../domain_and_spec/tournament.md).
- 훈련 기록 도메인은 `TOURNAMENT` 카테고리를 지원하지만, 이는 훈련 기록이며 대회별 입상/메달 집계 기능을 대체하지 않는다: [training-log.md](../domain_and_spec/training-log.md).
- 현재 사용자 간 훈련 기록 공유는 친구 공개 설정으로 별도 관리한다. 대회 성적 공개 정책도 이를 그대로 재사용한다고 가정하지 않고 별도 결정한다: [training-log-social.md](../domain_and_spec/training-log-social.md).
