# 훈련카드 연동 기획서

## 1. 문서 목적

- 현재 브랜치 `feature/training-log-card-content`에 맞춰 훈련카드 기능 범위를 정리한다.
- 이 문서는 기술 구현 방식이 아니라 사용자에게 어떤 기능을 제공할지와 어떤 흐름으로 풀어야 할지를 정의한다.
- 범위는 `훈련카드 조회`, `훈련카드 상세`, `훈련일지에 카드 추가`, `추가된 카드 읽기`까지로 제한한다.

## 2. 해결하려는 문제

- 사용자는 수업에서 들은 기술 이름을 금방 잊고, 훈련일지에 무엇을 써야 할지도 막막하다.
- 기술 이름만 알아서는 복기가 어렵고, 훈련일지와 연결되지 않으면 배운 내용을 다시 찾기 어렵다.
- 훈련일지에 “오늘 무엇을 배웠는지”를 남기더라도, 나중에 다시 읽을 때 기술 맥락이 부족할 수 있다.

## 3. 대상 사용자

- 주짓수를 배우며 기술을 복기하고 싶은 사용자
- 기술 이름은 들어봤지만 정리된 학습 자료가 필요한 사용자
- 훈련일지를 더 쉽게 쓰고, 나중에 다시 읽을 수 있게 만들고 싶은 사용자
- 현재 수준에 맞는 기술 카드만 골라서 보고 싶은 사용자

## 4. 제품 목표

- 사용자가 훈련카드 목록에서 배운 기술을 쉽게 찾을 수 있다.
- 카드 상세에서 기술 제목과 핵심 설명을 읽으며 복기할 수 있다.
- 훈련일지 생성/수정 중 관련 훈련카드를 붙여서 기록의 맥락을 남길 수 있다.
- 훈련일지 상세에서 그날 연결한 훈련카드를 다시 읽으며 복기 흐름을 완성한다.
- 카드별 좋아요와 즐겨찾기를 통해 다시 보고 싶은 기술을 빠르게 모을 수 있다.

## 5. 핵심 사용자 흐름

### 5.1 훈련카드 탐색

1. 사용자는 훈련카드 목록 화면에 진입한다.
2. 사용자는 목록 진입 직후 검색창과 `초급`, `중급`, `고급` 레벨 필터를 바로 볼 수 있어야 한다.
3. 사용자는 카드 목록에서 기술 제목과 요약 정보를 확인한다.
4. 필요하면 검색, 레벨, 포지션 기준으로 원하는 카드를 좁혀 본다.
5. 관심 있는 카드를 눌러 상세로 이동한다.

### 5.2 훈련카드 상세 복기

1. 사용자는 카드 상세에서 기술 제목을 확인한다.
2. 이 기술이 어떤 상황에서 쓰이는지, 무엇을 기억해야 하는지 읽는다.
3. 필요하면 유튜브 링크를 눌러 외부 영상으로 이동해 더 자세히 본다.
4. 좋아요 또는 즐겨찾기로 다시 보고 싶은 카드를 표시한다.
5. 필요하면 연관된 다른 카드도 이어서 본다.
6. 훈련일지를 쓰는 흐름 안이라면 이 카드를 기록에 추가한다.

### 5.3 훈련일지 작성 중 카드 연결

1. 사용자는 훈련일지 생성 또는 수정 화면에 들어간다.
2. `훈련카드 추가` 영역에서 오늘 배운 기술 카드를 찾는다.
3. 선택한 카드를 훈련일지에 연결한다.
4. 사용자는 제목/내용과 함께 연결된 카드를 보고 저장한다.

### 5.4 훈련일지 상세에서 다시 읽기

1. 사용자는 저장된 훈련일지 상세를 연다.
2. `이날 참고한 훈련카드` 영역에서 연결된 카드를 본다.
3. 카드 요약을 바로 읽거나 상세로 다시 들어간다.
4. 기록과 기술 설명을 함께 보며 복기한다.

## 6. 이번 범위

### 6.1 포함 기능

| 영역 | 기능 | 포함 기준 |
| --- | --- | --- |
| 탐색 | 훈련카드 목록 조회 | 사용자가 제목 중심으로 카드를 훑어볼 수 있어야 한다 |
| 탐색 | 검색 | 기술 제목 또는 핵심 키워드로 카드를 찾을 수 있어야 한다 |
| 탐색 | 기본 분류 | 포지션, 상황, 주제 기준으로 카드를 좁혀 볼 수 있어야 한다 |
| 탐색 | 레벨 필터 | `초급`, `중급`, `고급` 기준으로 카드를 걸러 볼 수 있어야 한다 |
| 탐색 | 포지션 필터 | `스탠딩`, `가드` 같은 기준으로 카드를 걸러 볼 수 있어야 한다 |
| 상세 | 훈련카드 상세 조회 | 카드의 제목과 복기용 설명을 읽을 수 있어야 한다 |
| 상세 | 유튜브 링크 이동 | 카드에 연결된 YouTube 링크를 눌러 유튜브로 이동할 수 있어야 한다 |
| 상세 | 좋아요 | 유용한 카드에 좋아요를 남길 수 있어야 한다 |
| 상세 | 즐겨찾기 | 다시 보고 싶은 카드를 즐겨찾기할 수 있어야 한다 |
| 상세 | 연관 카드 노출 | 비슷한 기술이나 다음에 볼 카드를 이어서 볼 수 있어야 한다 |
| 훈련일지 | 훈련일지 생성 시 카드 추가 | 기록 작성 중 관련 카드를 붙일 수 있어야 한다 |
| 훈련일지 | 훈련일지 수정 시 카드 추가/삭제 | 기록을 고치면서 연결 카드도 바꿀 수 있어야 한다 |
| 훈련일지 | 훈련일지 상세에서 연결 카드 읽기 | 저장된 기록에서 연결한 카드를 다시 확인할 수 있어야 한다 |

### 6.2 권장 MVP 제한

- 첫 출시에서도 특정 숙련도만 위한 기능으로 보이기보다, 기술마다 `초급`, `중급`, `고급` 레벨을 붙여 사용하는 방향이 좋다.
- 카드 연결은 `여러 개`를 허용하되, 한 기록에 너무 많이 붙지 않도록 적당한 개수 제한을 두는 편이 좋다.
- 카드 연결은 읽기와 복기 목적에 집중하고, 개인 메모나 평점 같은 부가 기능은 제외한다.

## 7. 훈련카드에 들어가면 좋은 정보

### 7.1 기본 정보

- 기술 제목
- 기술을 대표하는 짧은 소개 문장
- 기술 레벨 (`초급`, `중급`, `고급`)
- 어떤 분류에 속하는 기술인지
- 스탠딩인지 가드인지 같은 포지션 정보

### 7.2 설명은 충분히 길고 친절하게

- 한 줄 설명만으로 끝내기보다, 사용자가 “이 기술이 정확히 무엇인지” 이해할 수 있는 본문 설명이 들어가는 편이 좋다.
- 설명은 짧은 요약 1개와 상세 설명 여러 단락으로 나누는 구성이 좋다.
- 기술 이름보다 맥락 설명이 더 중요하므로, 카드 상세에서는 글의 밀도가 어느 정도 있는 편이 낫다.

권장 설명 구조:

- 이 기술이 무엇인지
- 어떤 상황에서 이 기술을 떠올리면 좋은지
- 상대와 내 몸의 위치가 어떤 상태인지
- 왜 이 기술이 통하는지
- 어느 수준의 사용자가 우선 익히면 좋은지

### 7.3 흐름도는 그림 대신 설명형 텍스트로 제공

- 복잡한 도식보다 “어떤 순서로 이어지는 기술인지”를 문장으로 따라가는 설명도 충분히 가치가 있다.
- 카드 안에 `기술 흐름` 또는 `진행 순서` 섹션을 두고, 처음 자세에서 마무리까지를 단계별 설명으로 적는 구성이 좋다.
- 이 섹션은 실제 도식 이미지가 없어도 “시작 -> 반응 유도 -> 진입 -> 연결 -> 마무리”처럼 읽히는 흐름이어야 한다.

권장 흐름 설명 형식:

1. 어떤 자세나 거리에서 시작하는지
2. 상대가 보이는 반응이나 빈틈이 무엇인지
3. 내가 먼저 만들어야 하는 핵심 동작이 무엇인지
4. 그 다음 연결 동작이 무엇인지
5. 마무리 또는 실패 시 다음 선택지가 무엇인지

### 7.4 카드 상세에 있으면 좋은 정보 묶음

- 기술 제목
- 짧은 소개 문장
- 기술 레벨 (`초급`, `중급`, `고급`)
- 포지션 정보 (`스탠딩`, `가드` 등)
- 어떤 상황에서 쓰는 기술인지
- 시작 자세 또는 전제 상황
- 기술 흐름 설명
- 핵심 포인트
- 자주 틀리는 점
- 주의할 점
- YouTube 링크
- 좋아요
- 즐겨찾기
- 같이 보면 좋은 연관 기술

## 8. 화면별 권장 구성

### 8.1 훈련카드 목록

- 카드마다 최소한 `기술 제목`, `짧은 설명`, `기본 분류`가 보이면 좋다.
- 제목만 길게 나열하기보다 짧은 설명이 함께 보이는 편이 낫다.
- 첫 화면은 `스탠딩`, `가드`, `패스`, `이스케이프`, `서브미션`처럼 사용자가 바로 이해할 수 있는 기준이 좋다.
- 목록만 보고도 “이 카드가 나한테 지금 필요한지” 판단할 수 있어야 한다.

목록 카드에 보이면 좋은 정보:

- 기술 제목
- 짧은 설명 또는 요약 문장
- 분류
- 기술 레벨 (`초급`, `중급`, `고급`)
- 포지션 정보 (`스탠딩`, `가드` 등)
- 어떤 상황에서 쓰는 기술인지 짧게 보여주는 문구

목록에서 어떻게 보이면 좋은가:

- 제목이 가장 먼저 눈에 들어와야 한다.
- 그 아래에 짧은 설명이 1~2줄 정도 보이면 좋다.
- `초급`, `중급`, `고급` 레벨은 배지처럼 바로 식별되는 방식이 좋다.
- `스탠딩`, `가드` 같은 포지션 정보도 빠르게 보이는 편이 좋다.
- 분류와 상황 정보는 너무 길지 않게 보조 정보로 붙는 편이 좋다.
- 카드가 전부 비슷하게 보이기보다, 지금 찾는 상황과 수준에 맞는 카드가 빨리 눈에 들어와야 한다.

목록에서 가능하면 바로 제공하면 좋은 것:

- 리스트 진입 시 바로 보이는 검색창
- 리스트 진입 시 바로 보이는 `초급`, `중급`, `고급` 필터
- 레벨 필터
- 포지션 필터
- 검색 결과와 필터 조합
- 즐겨찾기 여부 표시

리스트 진입 시 기본 상태 권장안:

- 상단에 검색창이 먼저 보인다.
- 검색창 아래 또는 같은 영역에 `초급`, `중급`, `고급` 필터가 바로 보인다.
- 사용자는 별도 메뉴를 더 열지 않아도 기본 레벨 필터를 바로 누를 수 있어야 한다.
- 검색과 레벨 필터는 함께 동작해야 한다.

권장 목록 우선순위:

- 사용자가 선택한 레벨 기준 우선
- 사용자가 선택한 포지션 기준 우선
- 제목만 알아도 바로 찾고 싶은 대표 기술 우선

목록에서 피하면 좋은 것:

- 제목만 있고 내용 맥락이 전혀 없는 카드
- 한 화면에 정보가 너무 많아 스캔이 어려운 카드
- `스탠딩`과 `가드`가 구분되지 않아 원하는 카드를 찾기 어려운 구성
- `초급`, `중급`, `고급` 차이가 드러나지 않아 난이도 판단이 어려운 구성

### 8.2 훈련카드 상세

- 기술 제목이 가장 먼저 보여야 한다.
- 상세는 “이 기술이 무엇인지”, “언제 쓰는지”, “무엇을 기억해야 하는지” 순서로 읽히는 구성이 좋다.
- 긴 설명도 구획이 나뉜 읽기 구조로 제공되면 더 잘 따라갈 수 있다.
- 따라서 상세는 한 줄 요약만 강조하기보다, 충분한 설명을 여러 구역으로 나눠 읽게 하는 편이 좋다.
- 카드 상세에서는 YouTube 링크를 눌렀을 때 외부 유튜브로 자연스럽게 이동할 수 있어야 한다.
- 카드 상세에서는 좋아요와 즐겨찾기를 바로 누를 수 있어야 한다.

권장 상세 읽기 순서:

1. 기술 제목
2. 짧은 소개
3. 기술 레벨과 포지션 정보
4. 이 기술이 쓰이는 상황
5. 시작 자세 또는 전제 조건
6. 기술 흐름 설명
7. 핵심 포인트
8. 자주 틀리는 점
9. 주의할 점
10. YouTube 링크
11. 좋아요/즐겨찾기
12. 연관 기술

### 8.3 훈련일지 생성/수정

- 제목/내용 입력 아래 또는 근처에 `오늘 배운 훈련카드` 영역을 두는 편이 자연스럽다.
- 카드 선택 후 현재 연결된 카드가 바로 보이고, 쉽게 제거하거나 다시 선택할 수 있어야 한다.
- 훈련일지의 본문을 대체하는 기능이 아니라, 기록을 도와주는 보조 정보로 보여야 한다.

### 8.4 훈련일지 상세

- 연결 카드가 기록 본문과 분리된 별도 영역으로 보이는 편이 읽기 좋다.
- 카드 제목만 보여주는 것보다 짧은 요약이 같이 있으면 다시 눌러보지 않아도 복기가 가능하다.
- 사용자는 필요하면 카드 상세로 다시 이동해 더 자세히 읽을 수 있어야 한다.

## 9. 제품 원칙

- 사용자가 “무슨 기술인지 모르겠다”는 상태에서 바로 이탈하지 않도록 쉬운 용어와 짧은 요약을 우선한다.
- 훈련카드는 독립 콘텐츠이면서도, 훈련일지를 더 쉽게 쓰게 도와주는 보조 장치여야 한다.
- 카드 탐색보다 훈련일지 작성 흐름이 무거워지지 않게 해야 한다.
- 첫 출시에서는 많이 넣기보다 “찾기 쉽고, 붙이기 쉽고, 다시 읽기 쉬운가”에 집중한다.
- 레벨과 포지션 정보는 카드 탐색의 핵심 기준으로 일관되게 노출되는 편이 좋다.
- 이 기능 작업은 운영환경에 지장을 주지 않는 범위에서 진행해야 한다.
- 기존 훈련일지 작성/조회, 소셜, 알림, 인사이트 같은 운영 중 기능의 정상 흐름을 깨지 않는 방식으로 추가되어야 한다.
- 새 기능은 가능하면 기존 사용자 흐름과 분리해 단계적으로 붙는 형태가 좋고, 운영 중인 화면과 API를 갑자기 대체하는 방식은 피하는 편이 좋다.
- 배포 후 문제가 생기면 빠르게 비활성화하거나 영향 범위를 좁힐 수 있는 구조를 우선 고려하는 편이 좋다.

## 10. 이번 범위에서 제외할 것

- 훈련카드 댓글
- 카드별 개인 진도율
- 카드 추천 알고리즘 고도화
- 카드 공유 기능
- 카드 편집 권한/운영 도구의 상세 설계
- 훈련일지 안에서 카드별 개인 메모를 별도로 남기는 기능

## 11. 성공 신호

- 사용자가 카드 목록에서 상세까지 자연스럽게 진입한다.
- 훈련일지 생성/수정 시 훈련카드를 함께 붙이는 비율이 의미 있게 나온다.
- 훈련일지 상세에서 연결 카드 재열람이 발생한다.
- 카드 상세에서 YouTube 링크 클릭이 실제 학습 보조로 사용된다.
- 좋아요와 즐겨찾기가 다시 보기 행동으로 이어진다.
- 사용자가 “오늘 배운 기술을 나중에 다시 찾기 쉬워졌다”는 체감을 얻는다.

## 12. 열린 결정 사항

- 레벨 기준을 누가 어떻게 관리할지
- 포지션 기준을 `스탠딩`, `가드`까지만 둘지 더 세분화할지
- 한 훈련일지에 연결 가능한 카드 수를 몇 개로 제한할지
- 카드 상세에 YouTube 링크를 1개만 둘지, 여러 개 둘지
- 훈련카드 목록 진입을 독립 메뉴로 줄지, 훈련일지 작성 흐름 안에서 먼저 노출할지

## 14. Phase별 체크리스트

### Phase 1. 계약과 범위 확정

- [ ] 훈련카드 도메인이 훈련일지 본체와 별도 도메인인지, 부속 확장인지 백엔드 기준으로 정리한다.
- [ ] 이번 출시 범위에 포함할 API를 확정한다.
- [ ] 리스트 조회, 상세 조회, 좋아요, 즐겨찾기, 훈련일지 연결 API의 우선순위를 정한다.
- [ ] `초급`, `중급`, `고급` 레벨 raw value를 확정한다.
- [ ] `스탠딩`, `가드` 등 포지션/분류 raw value를 확정한다.
- [ ] YouTube 링크 허용 기준과 저장 기준을 확정한다.
- [ ] 한 훈련일지에 연결 가능한 카드 수 기준을 확정한다.

### Phase 2. 도메인 모델 설계

- [ ] 훈련카드 기본 엔티티에 필요한 필드를 정의한다.
- [ ] 카드 본문 설명, 흐름 설명, 핵심 포인트, 주의사항 같은 상세 콘텐츠 구조를 정의한다.
- [ ] 카드 레벨, 포지션, 분류 모델을 정의한다.
- [ ] 좋아요/즐겨찾기 저장 모델이 별도 테이블인지 포함 모델인지 정한다.
- [ ] 훈련일지와 훈련카드 연결 모델을 정의한다.
- [ ] soft delete, 공개 여부, 노출 순서 같은 운영 필드가 필요한지 검토한다.

### Phase 3. 조회 API 설계

- [ ] 훈련카드 리스트 조회 API를 정의한다.
- [ ] 리스트 조회에서 검색 조건을 지원하도록 설계한다.
- [ ] 리스트 조회에서 `초급`, `중급`, `고급` 필터를 지원하도록 설계한다.
- [ ] 리스트 조회에서 `스탠딩`, `가드` 필터를 지원하도록 설계한다.
- [ ] 검색과 필터를 동시에 적용하는 계약을 정의한다.
- [ ] 리스트 응답에 제목, 요약, 레벨, 포지션, 즐겨찾기 여부 등 필요한 공개 필드를 정리한다.
- [ ] 훈련카드 상세 조회 API와 상세 응답 필드를 정의한다.
- [ ] 상세 응답에 YouTube 링크, 좋아요 수, 즐겨찾기 여부 포함 여부를 확정한다.

### Phase 4. 상호작용 API 설계

- [x] 카드 좋아요 추가/취소 API를 정의한다.
- [x] 카드 즐겨찾기 추가/취소 API를 정의한다.
- [x] 같은 사용자의 중복 좋아요/중복 즐겨찾기 처리 규칙을 정한다.
- [x] 좋아요/즐겨찾기 조회 책임이 리스트 응답인지 상세 응답인지 정리한다.
- [x] 훈련카드와 훈련일지 연결 추가/삭제 API 또는 훈련일지 생성/수정 payload 방식을 확정한다.

### Phase 5. 훈련일지 연동 설계

- [x] 훈련일지 생성 request에 훈련카드 연결 정보를 포함할지 정한다.
- [x] 훈련일지 수정 request에 연결 카드 변경 방식을 정의한다.
- [x] 훈련일지 상세 응답에서 연결 카드가 어떻게 내려갈지 정의한다.
- [x] 훈련일지 요약 응답에 연결 카드 노출이 필요한지 검토한다.
- [x] 기존 훈련일지 소셜/친구 열람 응답에 연결 카드가 필요한지 범위를 정한다.
- [x] 훈련일지 삭제 시 연결 카드 데이터 정리 정책을 정한다.

적용 메모:

- 훈련일지와 훈련카드 연결은 별도 전용 API 대신 `훈련일지 생성/수정 payload`의 `trainingCardIds`로 처리한다.
- 훈련일지 상세와 친구 상세에는 연결 카드 목록을 포함하고, 날짜별 요약 응답과 친구 피드 요약 응답은 이번 단계에서는 제외한다.
- 좋아요/즐겨찾기 중복 요청은 idempotent 하게 처리하고, 상태 표시는 훈련카드 리스트/상세 응답에서 내려준다.

### Phase 8. 성능과 운영 안정성

- [x] 카드 리스트 조회가 검색/필터 조건에서 안정적으로 동작하도록 조회 전략을 검토한다.
- [x] 훈련일지 상세에서 연결 카드 조회가 N+1을 만들지 않도록 확인한다.
- [x] 좋아요/즐겨찾기 수 집계 방식이 운영 부하를 키우지 않는지 검토한다.
- [x] 기존 훈련일지 작성/조회, 소셜, 알림, 인사이트 흐름을 깨지 않는지 확인한다.
- [x] 운영 중인 API를 갑자기 대체하지 않고 additive change로 갈 수 있는지 확인한다.
- [x] 장애 시 기능을 비활성화하거나 영향 범위를 줄일 수 있는 운영 방안을 검토한다.

적용 메모:

- 데이터/마이그레이션, 권한/보안, 운영 반영 메모는 `docs/domain_and_spec/training-card.md`에 정리한다.
- 기존 `training_log_entries` 테이블 컬럼 변경 없이 신규 카드/상호작용/조인 테이블만 additive 하게 추가한다.
- 카드 초기 데이터는 기능 노출 전 별도 적재가 필요하며, 마이그레이션과 애플리케이션 배포 후 seed -> smoke test -> 노출 순서를 권장한다.
- 현재 구현 기준 훈련카드 읽기/쓰기 API는 모두 인증 사용자만 허용하고, 카드 생성/수정/삭제 운영 API는 아직 미구현 상태로 `ADMIN` 전용 후보로 남긴다.
- 장애 시 `TRAINING_CARD_ENABLED=false`로 카드 조회/상호작용 기능을 비활성화하고, 훈련일지 응답의 연결 카드도 빈 배열로 축소할 수 있게 한다.
