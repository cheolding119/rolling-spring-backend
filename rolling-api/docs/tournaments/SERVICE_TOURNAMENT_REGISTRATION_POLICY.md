# 서비스용 대회 등록 정책서

## 1. 목적

이 문서는 Rolling 서비스에서 `대회 정보`를 어떤 기준으로 등록하고 노출할지 정리한 운영 정책서다.

목표는 두 가지다.

- 사용자가 필요한 대회 정보를 빠르게 찾을 수 있게 한다.
- 제3자 플랫폼이나 타 서비스의 데이터를 무리하게 복제하지 않고, 최소한의 사실 정보만 안전하게 다룬다.

## 2. 기본 원칙

Rolling의 대회 기능은 현재 `대회 운영 플랫폼`이 아니라 `대회 탐색 서비스`에 가깝다.

따라서 아래 원칙을 유지한다.

- 대회 정보는 `큐레이션형 탐색 데이터`로 운영한다.
- 원문이나 운영 상세를 통째로 복제하지 않는다.
- 사용자에게 필요한 `최소 사실 정보`만 저장한다.
- 가능하면 `원 주최측 출처`를 우선 확인한다.
- Spotlite처럼 실제 접수를 대행하는 플랫폼은 `공식 신청 경로`로 인정할 수 있다.

## 3. 현재 권장 등록 주체

### 3.1 지금 단계

- 관리자만 대회를 등록한다.
- 일반 사용자는 직접 공개 등록하지 않는다.
- 일반 사용자가 제보할 경우에도 `관리자 검토 후 등록` 방식으로만 처리한다.

### 3.2 이유

- 허위 대회, 중복 대회, 잘못된 신청 링크를 초기 단계에서 줄일 수 있다.
- 운영 품질을 유지하기 쉽다.
- 제3자 플랫폼 데이터 미러링처럼 보일 위험을 낮출 수 있다.

## 4. 허용 소스 정책

### 4.1 우선 소스

아래 소스를 우선 신뢰한다.

- 주최자 공식 홈페이지
- 주최자 공식 인스타그램, 블로그, 카페 등 공식 SNS
- 주최자 공식 신청 페이지
- 주최자가 접수 경로로 사용하는 Spotlite 대회 상세 또는 신청 페이지
- 연맹 또는 협회 공식 공지 페이지

### 4.2 보조 소스

아래 소스는 `발견용` 또는 `보조 검증용`으로만 사용한다.

- 커뮤니티 게시글
- 제3자 모음 페이지

### 4.3 운영 원칙

- 주최자가 Spotlite에서 접수를 받는 경우 `applyLink`는 Spotlite 상세 또는 신청 페이지를 사용할 수 있다.
- Spotlite를 신청 경로로 사용하더라도 Rolling에는 `최소 사실 정보`만 저장한다.
- 원 주최측 출처를 함께 찾을 수 있으면 출처 메모에 같이 남긴다.
- 보조 소스의 본문, 포스터, 운영 문구를 그대로 옮기지 않는다.

## 5. 저장 허용 필드

현재 서비스에서 기본으로 허용하는 필드는 아래다.

- `title`
- `competitionDate`
- `location`
- `organizer`
- `applyLink`

아래 필드는 `공식 출처에서 명확히 확인된 경우에만` 보조적으로 저장 가능하다.

- `registrationDeadline`

## 6. 저장 금지 또는 제한 필드

아래 정보는 원칙적으로 저장하지 않는다.

- 제3자 플랫폼의 포스터 이미지
- 공지 본문 전문
- 환불 규정 전문
- 입금 계좌 정보
- 문의처 문구 전문
- 참가자 명단
- 참가자 연락처
- 대진표
- 실시간 현황판 데이터
- 경기 결과 전체
- 세부 체급표 전체

이유는 아래와 같다.

- 사용자 탐색에 꼭 필요한 최소 범위를 넘는다.
- 저작권, 데이터베이스권, 개인정보 리스크가 커진다.
- 서비스가 탐색이 아니라 미러링처럼 보일 수 있다.

## 7. Spotlite 사용 규칙

Spotlite는 단순 정보 모음 페이지가 아니라 실제 대회 접수를 대행하는 플랫폼으로 볼 수 있다.
주최자가 Spotlite를 공식 접수 경로로 쓰는 경우 Rolling은 Spotlite 링크를 `applyLink`로 사용할 수 있다.

### 허용

- 대회 존재 여부 확인
- 대회명, 일정, 장소, 주최자, 신청 링크 같은 사실 정보 확인
- Spotlite 상세 또는 신청 페이지를 `applyLink`로 연결
- 출처 메모에 `sourceName = Spotlite`와 `sourceUrl` 기록

### 비권장

- 대회 상세 공지 문구 복사
- 환불 규정 복사
- 포스터 이미지 재업로드
- 참가자/대진표/결과 데이터 저장
- 주짓수 목록을 통째로 수동 미러링

## 8. 등록 절차

### 8.1 관리자 등록 플로우

1. 대회 후보를 발견한다.
2. 주최자가 실제 접수를 받는 경로를 확인한다.
3. 아래 최소 사실 정보를 확인한다.
- 대회명
- 날짜
- 장소
- 주최자
- 신청 링크
4. Spotlite가 공식 접수 경로라면 `applyLink`에 Spotlite 상세 또는 신청 페이지를 저장한다.
5. 확인된 정보만 등록한다.
6. 내부 메모로 출처 URL과 확인일을 남긴다.

### 8.2 출처 메모 권장 항목

- `sourceName`
- `sourceUrl`
- `verifiedAt`
- `verifiedBy`
- `sourceType`

권장 `sourceType` 예시:

- `OFFICIAL_SITE`
- `OFFICIAL_SOCIAL`
- `OFFICIAL_APPLICATION_PAGE`
- `OFFICIAL_REGISTRATION_PLATFORM`
- `THIRD_PARTY_PLATFORM`

## 9. 노출 정책

- 상세 화면은 `신청 페이지 이동` 중심으로 구성한다.
- Rolling은 전체 운영 정보를 다시 쓰는 곳이 아니라, 사용자를 `정확한 신청 경로`로 연결하는 곳으로 본다.
- 정보가 불명확하거나 출처 신뢰도가 낮으면 등록하지 않거나 숨김 처리한다.

## 10. 중복 등록 정책

- 동일 대회가 여러 출처에 보이더라도 하나의 대회로 합친다.
- 우선 식별 기준은 아래를 사용한다.
- `applyLink`
- `title + competitionDate`

동일 여부가 애매하면 아래 순서로 판단한다.

1. 신청 링크가 같은지
2. 제목과 날짜가 같은지
3. 장소와 주최자가 같은지
4. 원 출처가 같은지

## 11. 수정 및 삭제 정책

- 잘못된 정보 제보가 오면 우선 숨김 검토한다.
- 출처 확인이 안 되거나 링크가 잘못됐으면 즉시 수정 또는 비노출 처리한다.
- 권리자 또는 주최자가 삭제를 요청하면 우선 임시 비노출 후 사실관계를 확인한다.

## 12. 향후 확장 기준

아래 조건이 갖춰지기 전까지는 일반 사용자 직접 등록을 열지 않는다.

- 관리자 검수 프로세스가 정리되어 있을 것
- 중복 등록 기준이 안정적일 것
- 신고 처리 및 숨김 권한이 준비되어 있을 것
- 법적 이슈 발생 시 대응 창구가 있을 것

## 13. 현재 운영 결론

현재 Rolling의 대회 등록 정책은 아래로 정리한다.

- 대회는 `관리자 큐레이션형`으로 운영한다.
- Spotlite가 실제 접수 경로라면 `applyLink`로 사용할 수 있다.
- 저장은 `최소 사실 정보`만 한다.
- 포스터, 본문, 참가자 데이터 같은 확장 정보는 저장하지 않는다.
- 사용자는 상세에서 `신청 링크`로 이동한다.

이 정책은 대회 기능을 `탐색 서비스`로 유지하면서도, 운영 리스크와 법적 리스크를 함께 낮추는 현재 기준선이다.
