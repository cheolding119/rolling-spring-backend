# 훈련일지 친구/소셜 기능 초기 기획안

## 1. 문서 목적

- 개인 중심으로 시작한 훈련일지에 `친구`, `열람`, `좋아요`, `댓글` 기능을 붙이기 위한 초기 제품 기획안이다.
- 범위는 공개 SNS가 아니라 `친구 관계를 기반으로 한 제한적 공유`에 맞춘다.
- 이 문서는 초기 방향을 정하는 기준이며, 상세 도메인/API 문서는 `docs/domain_and_spec/training-log-social.md`에 둔다.

## 2. 배경

현재 훈련일지는 개인 기록과 복기에 강점이 있지만, 다음과 같은 한계가 있다.

- 사용자는 훈련한 내용을 혼자만 쌓고 끝내는 경우가 많다.
- 친한 팀원이나 코치에게 “내가 요즘 뭘 훈련하는지” 보여주기 어렵다.
- 훈련일지에 대한 피드백, 응원, 질문이 자연스럽게 붙지 않는다.
- 커뮤니티 글로 올리기에는 너무 개인적이고, 메신저로 공유하기에는 누적성이 약하다.

## 3. 해결하려는 문제

### 3.1 사용자 문제

- 사용자는 내 훈련 흐름을 친구와 가볍게 공유하고 싶다.
- 사용자는 친구의 훈련일지를 보며 동기부여를 받고 싶다.
- 사용자는 훈련일지에 간단한 피드백이나 응원을 남기고 싶다.
- 사용자는 공개 노출 없이 신뢰 관계 안에서만 기록을 공유하고 싶다.

### 3.2 제품 목표

- 개인 기록을 `관계 기반 기록`으로 확장한다.
- 훈련일지의 재방문율과 작성 지속성을 높인다.
- 친구 간 상호작용을 통해 훈련일지의 체류 시간을 늘린다.
- 공개 피드로 커지기 전에 제한된 범위에서 공유 니즈를 검증한다.

## 4. 권장 제품 방향

### 4.1 핵심 권장안

이번 기능은 `친구 전용 공유형 훈련일지`로 시작하는 것이 맞다.

- 공개 피드는 지금 넣지 않는다.
- `친구가 된 사용자만` 훈련일지를 볼 수 있게 한다.
- 훈련일지 작성자는 친구 설정에서 `훈련일지 친구 공개 on/off`를 선택할 수 있게 한다.
- 친구가 볼 수 있는 기록에만 좋아요와 댓글을 허용한다.
- 친구가 댓글을 남기면 기록 작성자에게 푸시 알림을 보낸다.
- 댓글은 1단계 대댓글까지 허용해 피드백 맥락을 이어갈 수 있게 한다.

이 방향을 권장하는 이유:

- 현재 훈련일지의 성격은 공개 콘텐츠보다 개인 복기 도구에 가깝다.
- 공개 피드까지 열면 신고, 노출 정책, 추천, 검색, 운영 도구가 함께 필요해진다.
- 친구 관계 기반으로 시작하면 사용자 가치 대비 운영 복잡도를 낮출 수 있다.

### 4.2 기본 친구 공개 설정 권장

기본값은 `친구에게 비공개`가 맞다.

- `shareWithFriends = false`: 친구에게 훈련일지 비공개
- `shareWithFriends = true`: 친구에게 훈련일지 공개

초기 버전에서는 `PUBLIC`을 넣지 않는 것을 권장한다.

## 5. 사용자 대상

### 5.1 1차 대상

- 같은 체육관 사람들
- 자주 같이 훈련하는 팀원
- 코치와 수강생
- 훈련 기록을 꾸준히 남기는 기존 사용자

### 5.2 기대 행동

- 친구 요청을 보낸다.
- 친구의 훈련일지를 본다.
- 좋아요로 가볍게 반응한다.
- 댓글로 피드백이나 질문을 남긴다.
- 댓글 알림을 받고 다시 기록으로 돌아온다.
- 공유받는 전제를 고려해 기록 작성 빈도가 증가한다.

## 6. 이번 범위 제안

### 6.1 지금 출시할 범위

#### A. 친구 관계

- 친구 검색 결과에 이름, 소속, 벨트 노출
- 친구 요청 보내기
- 받은 친구 요청 수락/거절
- 친구 목록 조회
- 친구 삭제

친구 관계는 `양방향 승인형`으로 간다.

이유:

- 훈련일지는 비교적 사적인 데이터다.
- 팔로우형보다 승인형이 사용자 기대와 보안 감각에 맞다.

#### B. 친구 훈련일지 공개 설정

- 친구 설정에서 `훈련일지 공개 on/off` 선택
- 친구 관계가 있어도 공개 설정이 꺼져 있으면 훈련일지가 보이지 않음
- 기존 사용자의 기본값은 `비공개`로 시작

#### C. 친구 훈련일지 열람

- 친구의 월간 캘린더 조회
- 친구의 특정 날짜 기록 목록 조회
- 친구의 훈련일지 상세 조회
- 친구 훈련일지는 `친구 공개 on` 상태일 때만 노출
- 차단 관계가 있으면 열람 불가

#### D. 좋아요

- 친구가 볼 수 있는 훈련일지에 좋아요 추가/취소
- 좋아요 수 표시
- 내가 좋아요 눌렀는지 표시

#### E. 댓글

- 댓글 목록 조회
- 댓글 작성
- 대댓글 작성
- 댓글과 대댓글 작성은 훈련일지 상세 페이지에서만 제공
- 본인 댓글 수정/삭제
- 작성자 또는 관리자 댓글 삭제 가능
- 친구가 댓글을 달면 기록 작성자에게 푸시 알림 발송
- 내 댓글에 대댓글이 달리면 댓글 작성자에게 푸시 알림 발송

### 6.2 다음 단계로 미룰 범위

- 좋아요 알림
- 친구 활동 피드
- 친구 추천
- 친구 검색 고도화
- 프로필에서 친구의 훈련 통계 요약 보기
- 친구의 출석 잔디/인사이트 열람

### 6.3 나중으로 미룰 범위

- 공개 피드
- 해시태그 기반 탐색
- 인기 기록 정렬
- 멘션
- 댓글 좋아요
- 기록 공유 링크
- 코치 전용 피드백 권한

## 7. 내가 추가로 권장하는 아이디어

### 7.1 친구 공개 설정은 꼭 넣는 것이 좋다

친구 기능만 넣고 친구 관계가 되는 즉시 모든 기록이 자동 공개되면 거부감이 생길 수 있다.

권장 정책:

- 기본값은 `친구 비공개`
- 사용자가 친구 설정에서 공개를 켠 경우에만 친구가 열람

### 7.2 친구 전용 탭이 필요하다

초기 UX는 복잡한 피드보다 `친구 훈련일지` 탭이 더 적합하다.

권장 구조:

- 내 훈련일지
- 친구 훈련일지

초기에는 친구 목록 기반 진입이 더 단순하다.

댓글/대댓글 UX 메모:

- 목록에서는 댓글 수만 보여주고 입력창은 두지 않는다.
- 댓글과 대댓글은 훈련일지 상세 페이지에서 작성한다.

친구 검색 UX 메모:

- 친구 검색 결과에는 이름, 소속, 벨트를 함께 노출한다.
- 닉네임 중복이 가능하므로 이름만으로 친구를 식별하지 않는다.

### 7.3 댓글은 피드백 성격에 맞게 정렬이 단순해야 한다

초기에는 댓글을 오래된 순 또는 생성 순으로만 보여주는 것이 좋다.

- 인기순 정렬 없음
- 1단계 대댓글만 허용
- 신고 기능은 초기엔 제외 가능

### 7.4 좋아요보다 댓글이 더 중요한 신호일 수 있다

좋아요는 진입 장벽이 낮지만, 훈련일지의 실질 가치는 댓글 피드백에서 더 많이 나온다.

따라서 초기 성공 판단에서는 좋아요 수보다 아래를 더 본다.

- 댓글이 달린 기록 비율
- 친구 열람 후 댓글 전환율

## 8. 상세 정책 제안

### 8.1 친구 정책

- 친구 검색은 이름 기반으로 수행한다.
- 친구 검색 결과에는 이름, 소속, 벨트를 함께 노출한다.
- 친구 요청은 활성 친구 관계가 없을 때만 가능
- 자기 자신에게 요청 불가
- 이미 친구면 재요청 불가
- 차단한 사용자 또는 차단당한 사용자와는 친구 요청 불가
- 탈퇴/비활성 사용자에게 요청 불가

### 8.2 열람 정책

- 작성자는 항상 본인 기록을 본다.
- 친구는 `shareWithFriends = true`인 사용자 기록만 본다.
- 공개 설정이 꺼져 있으면 친구도 볼 수 없다.
- 친구가 아니면 다른 사용자의 훈련일지를 볼 수 없다.
- 차단 관계가 생기면 기존 친구 관계보다 차단 정책이 우선한다.

### 8.3 좋아요 정책

- 좋아요는 친구가 열람 가능한 기록에만 허용
- 한 사용자당 한 기록에 좋아요 1개
- 본인 좋아요는 허용하지 않는다.

이유:

- 의미 없는 카운트를 줄이고 신호 해석이 쉬워진다.

### 8.4 댓글 정책

- 댓글은 친구가 열람 가능한 기록에만 작성 가능
- 댓글 작성자는 기록 작성자와 친구여야 한다.
- 대댓글 작성자는 상위 댓글 또는 기록 작성자와 친구여야 한다.
- 본인 댓글만 수정 가능
- 본인 댓글과 내 기록에 달린 댓글은 삭제 가능
- 대댓글은 1단계까지만 허용한다.
- 대댓글에는 다시 대댓글을 달 수 없다.
- 삭제된 댓글에 대댓글이 있어도 스레드 구조는 유지되어야 한다.
- 친구가 내 기록에 댓글을 달면 기록 작성자에게 푸시 알림을 보낸다.
- 내 댓글에 대댓글이 달리면 상위 댓글 작성자에게 푸시 알림을 보낸다.
- 본인 액션에 대한 자기 알림은 보내지 않는다.

### 8.5 운영 정책

- 관리자 숨김/신고 처리 도구는 초기 범위에서 제외 가능
- 다만 abuse 위험이 빠르게 보이면 댓글 신고와 관리자 삭제 기능을 다음 우선순위로 올린다.

## 9. 권장 사용자 흐름

### 9.1 친구 연결

1. 사용자가 이름으로 다른 사용자를 검색한다.
2. 검색 결과에서 이름, 소속, 벨트를 보고 대상을 식별한다.
3. 친구 요청을 보낸다.
4. 상대 사용자가 수락한다.
5. 둘은 친구 관계가 된다.

### 9.2 친구에게 기록 공유

1. 사용자가 훈련일지를 작성한다.
2. 친구 설정에서 `친구에게 훈련일지 공개`를 켠다.
3. 그 후 친구는 내 월간 캘린더, 날짜별 기록 목록, 상세를 볼 수 있다.

### 9.3 친구 기록 상호작용

1. 친구가 친구 훈련일지 탭에 진입한다.
2. 친구 목록 또는 최신 공유 기록을 본다.
3. 특정 기록 상세에 들어간다.
4. 상세 페이지에서 좋아요를 누르거나 댓글을 남긴다.
5. 댓글 알림을 받으면 해당 기록 상세로 다시 진입한다.

## 11. API 방향 초안

### 11.1 친구

- `GET /api/v1/friends/search?q={nickname}`
- `GET /api/v1/friends`
- `GET /api/v1/friends/requests/received`
- `GET /api/v1/friends/requests/sent`
- `POST /api/v1/friends/requests/{targetUserId}`
- `POST /api/v1/friends/requests/{requestId}/accept`
- `POST /api/v1/friends/requests/{requestId}/reject`
- `DELETE /api/v1/friends/{friendUserId}`

### 11.2 친구 훈련일지 조회

- `GET /api/v1/training-logs/friends/{friendUserId}/calendar?year={year}&month={month}`
- `GET /api/v1/training-logs/friends/{friendUserId}/entries?date={yyyy-MM-dd}`
- `GET /api/v1/training-logs/friends/entries/{entryId}`

### 11.3 좋아요

- `POST /api/v1/training-logs/entries/{entryId}/like`
- `DELETE /api/v1/training-logs/entries/{entryId}/like`

### 11.4 댓글

- `GET /api/v1/training-logs/entries/{entryId}/comments`
- `POST /api/v1/training-logs/entries/{entryId}/comments`
- `PATCH /api/v1/training-logs/comments/{commentId}`
- `DELETE /api/v1/training-logs/comments/{commentId}`

댓글 request 방향:

- 일반 댓글: `parentCommentId = null`
- 대댓글: `parentCommentId = 상위 댓글 ID`

### 11.5 알림

- `GET /api/v1/notifications`
- `GET /api/v1/notifications/badge`
- `PATCH /api/v1/notifications/{id}/read`

알림 타입 초안:

- `TRAINING_LOG_COMMENT_CREATED`
- `TRAINING_LOG_COMMENT_REPLY_CREATED`

설계 메모:

- 기존 개인 API인 `/api/v1/training-logs/me/*`와 분리하는 것이 맞다.
- 친구 열람용 API는 `/me` 경로에 넣지 않는 것을 권장한다.
- 커뮤니티의 좋아요/댓글 패턴을 재사용하면 구현 비용을 줄일 수 있다.
- 알림 저장과 푸시 발송은 기존 `Notification` 도메인 패턴을 재사용하는 것이 맞다.

## 12. 성공 지표

### 12.1 출시 후 1차 확인 지표

- 친구 요청 전송 사용자 수
- 친구 요청 수락률
- 친구 관계를 1명 이상 만든 사용자 비율
- 친구 훈련일지 공개 설정을 켠 사용자 비율
- 친구 기록 상세 조회 수
- 좋아요가 1개 이상 달린 기록 비율
- 댓글이 1개 이상 달린 기록 비율
- 댓글 알림 클릭 후 기록 상세 재진입률

### 12.2 더 중요한 학습 지표

- 친구 기능을 쓴 사용자의 기록 작성 유지율
- 친구를 맺은 이후 주간 기록 수 변화
- 댓글 받은 사용자의 재방문율
- 대댓글이 발생한 댓글 비율

## 13. 주요 트레이드오프

### 13.1 친구형 vs 팔로우형

권장: 친구형

- 장점: 사적 기록 공유에 맞다.
- 단점: 관계 형성 진입 비용이 더 높다.

### 13.2 전면 공유 vs 친구 설정 기반 공유

권장: 친구 설정 기반 공유

- 장점: 사용자 통제감이 높고 UI가 단순하다.
- 단점: 특정 기록만 선별 공개하는 유연성은 낮다.

### 13.3 1단계 대댓글 vs 무제한 스레드

권장: 1단계 대댓글

- 장점: 대화 맥락을 만들면서도 UI와 운영 복잡도를 통제할 수 있다.
- 단점: 긴 토론에는 제약이 있다.

### 13.4 댓글 신고 포함 vs 제외

권장: 초기 제외

- 장점: 빠르게 출시 가능하다.
- 단점: abuse 대응 수단이 부족하다.

대신 차단 정책과 관리자 삭제를 후속 우선순위로 준비해야 한다.

## 14. 리스크와 완화

### 14.1 사생활 침해 우려

리스크:

- 사용자가 원치 않는 기록까지 친구에게 노출될 수 있다.

완화:

- 기본값 `친구 비공개`
- 친구 설정에서 공개 여부 선택
- 친구 삭제와 차단을 쉬운 위치에 제공

### 14.2 관계 그래프 대비 사용성 저하

리스크:

- 친구가 적으면 피드가 비어 보일 수 있다.

완화:

- 비어 있는 상태에서 친구 요청 유도
- 친구 공개 설정이 꺼져 있거나 공개 기록이 없을 때 빈 상태 문구 제공

### 14.3 댓글 운영 리스크

리스크:

- 악성 댓글, 장난성 댓글 가능성

완화:

- 초기에는 친구 관계 안에서만 허용
- 차단 정책 우선 적용
- 관리자 삭제 기능 또는 신고 기능을 다음 단계 후보로 둠

### 14.4 알림 피로 리스크

리스크:

- 댓글과 대댓글이 늘면 알림이 과도하게 쌓일 수 있다.

완화:

- 자기 액션은 알림 발송 제외
- 좋아요 알림은 초기 범위에서 제외
- 배지와 알림함은 기존 공통 알림 정책 재사용

### 14.5 구현 범위 과대화

리스크:

- 친구, 피드, 알림, 공개 노출, 대댓글을 한 번에 넣으면 일정이 커진다.

완화:

- 이번 출시에서는 `친구 관계 + 친구 열람 + 좋아요 + 1단계 대댓글 + 댓글 푸시 알림`까지만 제한

## 15. 수용 기준

### 15.1 친구

- 사용자는 다른 활성 사용자에게 친구 요청을 보낼 수 있다.
- 사용자는 받은 요청을 수락/거절할 수 있다.
- 친구 관계가 되면 양쪽 친구 목록에서 서로를 볼 수 있다.
- 차단 관계가 있으면 친구 요청과 친구 열람이 불가능하다.

### 15.2 친구 공개 설정

- 사용자는 친구 설정에서 훈련일지 공개 여부를 변경할 수 있다.
- 기본값은 친구 비공개다.
- 친구는 친구 관계와 공개 설정이 모두 충족될 때만 훈련일지를 조회할 수 있다.

### 15.3 좋아요

- 친구가 열람 가능한 기록에만 좋아요를 누를 수 있다.
- 같은 사용자는 같은 기록에 1번만 좋아요할 수 있다.
- 본인 기록에는 좋아요를 누를 수 없다.
- 좋아요 취소가 가능하다.

### 15.4 댓글

- 친구가 열람 가능한 기록에 댓글을 작성할 수 있다.
- 댓글 목록을 조회할 수 있다.
- 댓글에 대댓글을 작성할 수 있다.
- 댓글과 대댓글 작성은 훈련일지 상세 페이지에서 가능하다.
- 댓글 작성자는 본인 댓글을 수정/삭제할 수 있다.
- 기록 작성자는 내 기록에 달린 댓글을 삭제할 수 있다.
- 대댓글은 1단계까지만 제공한다.
- 친구가 내 기록에 댓글을 달면 내 알림함과 푸시에 알림이 생성된다.
- 내 댓글에 대댓글이 달리면 내 알림함과 푸시에 알림이 생성된다.
- 자기 자신의 댓글/대댓글 액션에는 알림이 생성되지 않는다.

## 16. 미해결 의사결정

### 제품 책임자 판단 필요

- 친구 훈련일지 첫 화면을 `친구 목록 기반`으로 할지, `캘린더 기반`으로 할지
- 공개 설정을 켰을 때 과거 기록까지 모두 보여줄지, 설정 이후 기록만 보여줄지

### 엔지니어링 확인 필요

- 친구 검색의 prefix 매칭과 contains 매칭 중 어떤 검색 기준을 기본값으로 둘지
- 좋아요/댓글 수를 집계 쿼리로 계산할지 캐시 컬럼으로 유지할지
- 알림 route의 최종 앱 경로 문자열을 프론트 라우팅과 어떻게 맞출지
