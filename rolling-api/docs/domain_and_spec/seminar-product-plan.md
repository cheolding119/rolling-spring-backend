# 세미나 기획서

## 1. 문서 목적

- 세미나는 호스트가 주짓수 세미나를 오픈하고, 사용자가 정보를 확인한 뒤 참석 신청까지 완료하는 것을 핵심 목표로 한다.
- 이 문서는 세미나 기능의 제품 범위, 우선순위, 사용자 흐름, 운영 정책, 수용 기준을 정리한다.
- 상세 API 계약, enum raw value, request/response 필드는 별도 [seminar.md](seminar.md)에 작성한다.

## 2. 제품 목표

### 2.1 사용자 문제

- 참가자는 세미나 일정, 장소, 강사, 가격, 정원, 준비물, 환불 기준을 한곳에서 확인하고 빠르게 참석 신청하고 싶다.
- 호스트는 세미나를 홍보하고, 신청자 현황을 관리하며, 일정 변경 또는 취소 같은 운영 이슈를 참가자에게 안정적으로 전달하고 싶다.
- 운영자는 부적절한 게시물, 허위 세미나, 신고, 환불 분쟁, 사용자 제재 이슈를 추적할 수 있어야 한다.

### 2.2 성공 신호

- 세미나 목록에서 상세 진입률
- 상세 화면에서 참석 신청 전환율
- 신청 완료 후 취소율
- 호스트의 신청자 관리 사용률
- 신고 또는 문의로 이어지는 운영 이슈 비율
- 세미나 종료 후 실제 참석 확인 또는 후기 작성률

## 3. 대상 사용자

### 3.1 참가자

- 관심 지역과 일정에 맞는 세미나를 찾는다.
- 강사, 주제, 가격, 준비물을 확인한다.
- 참석 신청, 취소, 대기 신청 상태를 확인한다.
- 일정 변경, 장소 변경, 취소 알림을 받는다.

### 3.2 호스트

- 세미나 정보를 등록하고 모집 상태를 관리한다.
- 신청자 목록, 취소자, 대기자를 확인한다.
- 필요 시 참가자를 강제 취소하거나 모집을 마감한다.
- 공지 또는 변경 사항을 참가자에게 전달한다.

### 3.3 관리자

- 신고된 세미나와 사용자를 확인한다.
- 부적절한 세미나를 숨김, 삭제, 제재 처리한다.
- 세미나 운영 이슈를 문의, 신고, 사용자 제재 정책과 연결해 처리한다.

## 4. 핵심 사용자 흐름

### 4.1 세미나 탐색

1. 사용자는 세미나 목록에 진입한다.
2. 지역, 날짜, 모집 상태, 검색어로 세미나를 필터링한다.
3. 세미나 카드에서 제목, 강사, 일정, 장소, 가격, 남은 정원을 확인한다.
4. 상세 화면으로 진입해 신청 조건과 환불 기준을 확인한다.

### 4.2 세미나 참석 신청

1. 사용자는 상세 화면에서 참석 신청을 누른다.
2. 로그인하지 않은 사용자는 로그인 안내를 받는다.
3. 신청 전 필수 확인 항목을 확인한다.
4. 정원, 모집 상태, 자기 주최 여부, 제재 여부, 중복 신청 여부를 검증한다.
5. 신청이 완료되면 `APPLIED` 상태가 되고 알림함에 신청 완료 알림이 저장된다.

### 4.3 신청 취소

1. 참가자는 내 신청 목록 또는 세미나 상세에서 취소를 요청한다.
2. 취소 가능 시간과 환불 기준을 확인한다.
3. 취소가 완료되면 참가자 상태는 `CANCELED`가 된다.
4. 대기자가 있으면 정책에 따라 다음 대기자를 자동 승인하거나 호스트 수동 승인 대상으로 둔다.

### 4.4 호스트 등록 및 관리

1. 호스트는 세미나 기본 정보, 일정, 장소, 강사, 정원, 가격, 신청 안내,인스타 ID(선택) , 를 입력한다.
2. 등록 후 기본 모집 상태는 `RECRUITING`이다.
3. 호스트는 상세 화면에서 신청자 목록과 상태별 인원을 확인한다.
4. 호스트는 모집 상태를 `RECRUITING`, `CLOSED`, `CANCELED`로 변경할 수 있다.
5. 일정, 장소, 가격, 정원 같은 핵심 정보 변경 시 기존 신청자에게 알림을 저장한다.

### 4.5 운영 신고

1. 사용자는 허위 정보, 부적절한 내용, 광고/도배, 기타 사유로 세미나를 신고한다.
2. 동일 사용자의 중복 신고는 막는다.
3. 신고 누적 또는 관리자 판단에 따라 세미나 노출 제한, 삭제, 사용자 제재로 이어질 수 있다.

## 5. 기능 범위

### 5.1 지금 출시할 범위

세미나 MVP는 "세미나를 등록하고, 사용자가 참석 신청하며, 호스트가 신청자를 관리할 수 있는 기능"에 집중한다.

| 영역 | 기능 | 포함 기준 |
| --- | --- | --- |
| 조회 | 세미나 목록 | 공개 조회, 지역/상태/검색어/날짜 필터, 페이징 |
| 조회 | 세미나 상세 | 공개 조회, 강사/일정/장소/가격/정원/신청 상태 노출 |
| 등록 | 세미나 생성 | 인증 사용자만 가능, 필수 정보 validation |
| 수정 | 세미나 수정 | 호스트만 가능, 핵심 정보 변경 시 신청자 알림 |
| 삭제 | 세미나 삭제 | 호스트만 가능, soft delete, 신청자 알림 |
| 신청 | 참석 신청 | 인증 사용자만 가능, 정원/상태/중복/자기 주최 검증 |
| 신청 | 참석 취소 | 참가자 본인 취소, 취소 상태 기록 |
| 관리 | 신청자 목록 | 호스트 전용, 상태별 참가자 확인 |
| 관리 | 참가자 강제 취소 | 호스트 전용, 사유 선택 또는 메모 |
| 관리 | 모집 상태 변경 | 호스트 전용, `RECRUITING`, `CLOSED`, `CANCELED` |
| 알림 | 주요 상태 알림 | 신청 완료, 취소, 일정/장소 변경, 삭제, 모집 취소 |
| 신고 | 세미나 신고 | 인증 사용자만 가능, 중복 신고 방지 |
| 마이페이지 | 내 신청 세미나 | 인증 사용자 기준 신청 목록 |
| 마이페이지 | 내가 만든 세미나 | 인증 사용자 기준 주최 목록 |

### 5.2 다음 출시 범위

| 영역 | 기능 | 뒤로 미루는 이유 |
| --- | --- | --- |
| 대기 | 대기 신청 | MVP에서 상태 복잡도와 알림 분기 증가 |
| 체크인 | 현장 참석 확인 | 현장 운영 방식이 아직 검증되지 않음 |
| 후기 | 세미나 후기 | 종료 후 품질 신호로 유용하지만 신청 흐름 이후 가치 |
| 결제 | 앱 내 결제 | 결제, 환불, 정산, CS 부담이 큼 |
| 쿠폰 | 할인 코드 | 결제 정책 확정 후 설계해야 함 |
| 고급 검색 | 강사/벨트/기술 태그 검색 | 데이터 품질이 쌓인 뒤 효과가 커짐 |
| 호스트 공지 | 참가자 대상 공지 발송 | 알림 정책과 스팸 방지 기준 필요 |

### 5.3 나중에 검토할 범위

- 호스트 프로필과 주최 이력
- 외부 티켓 링크 연동
- 세미나 즐겨찾기
- 캘린더 추가
- 참가자 명단 CSV 다운로드
- 관리자 승인 후 게시
- 추천 세미나 피드

## 7. 상태 모델 초안

### 7.1 세미나 상태

| 상태 | 의미 | 전환 조건 |
| --- | --- | --- |
| `RECRUITING` | 모집 중 | 생성 기본값 또는 호스트 수동 재개 |
| `CLOSED` | 모집 마감 | 정원 도달, 신청 마감, 호스트 수동 마감 |
| `CANCELED` | 세미나 취소 | 호스트 또는 관리자 취소 |
| `FINISHED` | 종료 | 종료 시간이 지난 뒤 배치 또는 조회 시점 계산 |
| `DELETED` | 삭제됨 | soft delete 처리 |

정원 제한이 없는 세미나는 `maxCapacity = -1`로 표현하는 기존 오픈매트 규칙을 재사용하는 것을 우선 검토한다.

### 7.2 참석 신청 상태

| 상태 | 의미 |
| --- | --- |
| `APPLIED` | 참석 신청 완료 |
| `CANCELED` | 참가자 본인 취소 |
| `HOST_CANCELED` | 호스트 강제 취소 |
| `SEMINAR_CANCELED` | 세미나 취소로 인한 취소 |
| `ATTENDED` | 실제 참석 확인 |
| `NO_SHOW` | 미참석 |

MVP에서는 `APPLIED`, `CANCELED`, `HOST_CANCELED`, `SEMINAR_CANCELED`까지 구현하고, `ATTENDED`, `NO_SHOW`는 체크인 기능과 함께 다음 범위로 둔다.

## 8. 주요 정책

### 8.1 권한

- 목록과 상세 조회는 공개 API로 제공한다.
- 참석 신청, 취소, 신고, 내 목록 조회는 인증이 필요하다.
- 세미나 생성, 수정, 삭제, 신청자 관리는 인증 사용자가 수행한다.
- 작성자는 자신이 만든 세미나에 참석 신청할 수 없다.
- 관리자 제재 상태의 사용자는 세미나 생성과 참석 신청이 제한된다.

### 8.2 노출과 차단

- 로그인 사용자가 차단한 작성자의 세미나는 목록과 상세에서 숨긴다.
- 비회원 조회는 차단 필터 없이 공개 세미나만 보여준다.
- soft delete된 세미나는 일반 사용자에게 `NOT_FOUND`로 처리한다.
- 삭제 알림을 받은 신청자, 호스트, 관리자에게는 삭제 정보를 제한적으로 노출할 수 있다.

### 8.3 정원

- `maxCapacity > 0`이면 `APPLIED` 상태 인원 기준으로 정원을 계산한다.
- 정원 도달 시 자동으로 `CLOSED` 처리할 수 있다.
- 취소로 빈자리가 생기면 MVP에서는 호스트가 수동으로 `RECRUITING`으로 되돌리는 방식을 기본값으로 한다.
- 자동 대기자 승인은 다음 출시 범위로 둔다.

### 8.4 일정 변경

- 시작 일시, 종료 일시, 장소, 주소가 변경되면 신청자에게 알림을 저장한다.
- 신청 마감 이후 핵심 정보 변경은 허용하되, 변경 이력이 남아야 한다.
- 종료된 세미나는 일반 수정이 불가능해야 한다.

### 8.5 취소

- 참가자 취소는 시작 전까지 허용한다.
- 호스트 강제 취소는 시작 전까지 허용한다.
- 세미나 취소 시 모든 `APPLIED` 신청은 `SEMINAR_CANCELED`로 전환한다.
- 결제 기능이 없는 MVP에서는 환불 처리는 외부 안내 문구로만 관리한다.

### 8.6 신고

- 세미나 작성자는 자신의 세미나를 신고할 수 없다.
- 동일 사용자는 같은 세미나를 한 번만 신고할 수 있다.
- 신고 사유는 기존 신고 정책과 맞춰 `FALSE_INFO`, `INAPPROPRIATE`, `SPAM`, `OTHER`를 사용한다.
- 신고 누적에 따른 자동 숨김 여부는 관리자 정책과 함께 결정한다.

## 9. 알림

MVP에서 저장해야 하는 알림:

- 세미나 참석 신청 완료
- 세미나 참석 신청 취소
- 호스트의 참가자 강제 취소
- 세미나 일정 또는 장소 변경
- 세미나 삭제
- 세미나 취소

알림의 source of truth는 FCM 성공 여부가 아니라 백엔드 `Notification` 저장 데이터라는 기존 정책을 따른다.

## 10. 화면 요구사항

### 10.1 사용자 앱

- 세미나 목록
- 세미나 상세
- 세미나 작성
- 세미나 수정
- 참석 신청 확인
- 내 신청 세미나
- 내가 만든 세미나
- 신청자 목록과 관리 화면
- 신고 화면

### 10.2 관리자

- 신고된 세미나 목록
- 세미나 상세 운영 정보
- 관리자 숨김 또는 삭제 처리
- 신고 이력 확인
- 작성자 제재 연결

관리자 화면은 MVP 필수 앱 화면은 아니지만, 운영자가 최소한 DB 또는 기존 관리자 도구로 확인할 수 있는 데이터 구조는 MVP에서 준비해야 한다.

## 11. API 설계 방향

상세 계약은 [seminar.md](seminar.md)에 작성한다. 제품 관점에서 필요한 API 후보는 다음과 같다.

| 목적 | Method | Path |
| --- | --- | --- |
| 목록 조회 | `GET` | `/api/v1/seminars` |
| 상세 조회 | `GET` | `/api/v1/seminars/{id}` |
| 생성 | `POST` | `/api/v1/seminars` |
| 수정 | `PUT` | `/api/v1/seminars/{id}` |
| 삭제 | `DELETE` | `/api/v1/seminars/{id}` |
| 참석 신청 | `POST` | `/api/v1/seminars/{id}/applications` |
| 참석 취소 | `DELETE` | `/api/v1/seminars/{id}/applications/me` |
| 신청자 목록 | `GET` | `/api/v1/seminars/{id}/applications` |
| 참가자 강제 취소 | `PATCH` | `/api/v1/seminars/{id}/applications/{applicationId}/cancel` |
| 모집 상태 변경 | `PATCH` | `/api/v1/seminars/{id}/status` |
| 내 신청 목록 | `GET` | `/api/v1/seminars/my-applications` |
| 내 주최 목록 | `GET` | `/api/v1/seminars/my` |
| 신고 | `POST` | `/api/v1/seminars/{id}/reports` |

## 12. 수용 기준

### 12.1 참가자

- 사용자는 비로그인 상태로 세미나 목록과 상세를 볼 수 있다.
- 로그인 사용자는 모집 중이고 정원이 남은 세미나에 참석 신청할 수 있다.
- 사용자는 같은 세미나에 중복 신청할 수 없다.
- 사용자는 자신이 주최한 세미나에 신청할 수 없다.
- 사용자는 시작 전 자신의 신청을 취소할 수 있다.
- 사용자는 내 신청 세미나 목록에서 현재 신청 상태를 확인할 수 있다.

### 12.2 호스트

- 호스트는 필수 정보를 입력해 세미나를 생성할 수 있다.
- 호스트만 자신의 세미나를 수정, 삭제, 모집 상태 변경할 수 있다.
- 호스트는 신청자 목록을 상태별로 확인할 수 있다.
- 호스트는 참가자를 강제 취소할 수 있고, 취소된 참가자는 알림을 받는다.
- 호스트가 일정 또는 장소를 변경하면 신청자에게 알림이 저장된다.

### 12.3 운영

- 신고는 인증 사용자만 가능하고, 동일 사용자의 중복 신고는 실패한다.
- 삭제된 세미나는 일반 목록과 상세에서 노출되지 않는다.
- 차단한 작성자의 세미나는 로그인 사용자 목록과 상세에서 숨겨진다.
- 제재 사용자는 세미나 생성과 참석 신청이 차단된다.

## 13. 리스크와 완화

| 리스크 | 영향 | 완화 |
| --- | --- | --- |
| 결제 없이 신청만 제공하면 실제 참석 확정성이 낮을 수 있음 | 노쇼 증가 | 신청 안내, 외부 결제 안내, 취소 정책 명시 |
| 대기 신청을 제외하면 정원 취소 후 빈자리 회복이 수동임 | 호스트 관리 부담 | MVP에서는 호스트 수동 재오픈, 다음 버전에서 대기 기능 |
| 일정/장소 변경 알림 누락 | 참가자 불만 | 핵심 필드 변경 감지와 Notification 저장 테스트 |
| 신고/사기 대응 부족 | 신뢰 하락 | 신고 데이터 구조와 관리자 확인 경로를 MVP에 포함 |
| 세미나와 오픈매트 기능 중복 | 구현 복잡도 증가 | 신청, 차단, 신고, 알림 정책은 기존 도메인 규칙 재사용 |
