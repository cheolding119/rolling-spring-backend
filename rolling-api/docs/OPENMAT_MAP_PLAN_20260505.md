# 오픈매트 지도 기능 기획안

작성일: 2026-05-05
대상: Rolling Flutter 앱, Rolling API, 관리자 웹
범위: 오픈매트 상세 지도 미리보기, 오픈매트 생성/수정 시 장소 검색 및 좌표 저장

## 1. 배경

오픈매트는 실제 장소로 이동해야 하는 오프라인 이벤트다. 현재 오픈매트 장소 정보는 문자열 장소명과 주소에 의존하므로, 사용자는 주소를 복사해서 별도 지도 앱에서 검색해야 한다.

MVP에서는 대회 지도는 제외하고 오픈매트에만 지도 기능을 적용한다. 대회는 크롤링 또는 포스터 기반 장소 문자열 품질이 일정하지 않으므로, 장소 데이터 정규화 이후 후속으로 검토한다.

## 2. 목표

- 사용자가 오픈매트 상세 화면에서 위치를 즉시 이해한다.
- 오픈매트 생성/수정 시 사용자가 검색 후보 중 실제 장소를 선택한다.
- 선택한 장소의 위도/경도를 서버에 저장한다.
- 상세 화면은 저장된 좌표로 지도 미리보기를 표시한다.
- 좌표가 없는 기존 오픈매트도 화면이 깨지지 않는다.

## 3. 범위

### 지금 출시할 범위

1. 오픈매트 생성/수정 화면에 장소명 또는 주소 검색 입력창 추가
2. 카카오 장소/주소 검색 결과 후보 목록 표시
3. 사용자가 후보 중 실제 장소 선택
4. 선택한 장소명, 주소, 위도, 경도 저장
5. 오픈매트 상세 화면에서 저장 좌표로 카카오맵 WebView 지도 미리보기 표시
6. 카카오맵 앱 또는 카카오맵 웹 열기
7. 좌표 없는 오픈매트 fallback 처리

### 제외 범위

1. 대회 상세 지도 표시
2. 대회 좌표 저장
3. 목록 화면 지도 탐색
4. 내 위치 기준 거리순 정렬
5. 반경 검색
6. 자체 길찾기
7. 실시간 교통/대중교통 경로 계산
8. 사용자 위치 상시 수집
9. MVP의 수동 핀 이동

## 4. 사용자 흐름

### 오픈매트 생성/수정

```text
오픈매트 생성/수정 화면
        |
        | 장소명 또는 주소 입력
        v
카카오 장소/주소 검색 결과 후보 목록
        |
        | 사용자가 실제 장소 선택
        v
장소명 + 주소 + 위도 + 경도 확보
        |
        v
지도 미리보기 확인
        |
        v
POST/PUT API로 서버 저장
```

### 오픈매트 상세

```text
오픈매트 상세 화면
        |
        | 서버 응답에 latitude/longitude 있음
        v
지도 미리보기 + 마커 표시
        |
        | 지도에서 보기 클릭
        v
카카오맵 앱 또는 카카오맵 웹 fallback
```

좌표가 없으면 기존처럼 장소명과 주소만 표시한다.

## 5. UI 요구사항

### 상세 화면

- 장소명
- 주소
- 지도 미리보기
- 지도에서 보기
- 주소 복사

### 생성/수정 화면

- 장소명 또는 주소 검색 입력창
- 카카오 장소/주소 검색 결과 후보 목록
- 후보 선택 후 지도 미리보기
- 선택한 장소명, 주소, 위도, 경도 저장
- 검색 결과가 없을 때 수정 안내
- MVP에서는 수동 핀 이동 제외

중요: 자유 텍스트 주소를 자동 좌표 변환해서 바로 저장하지 않는다. 사용자가 검색 결과 후보를 보고 실제 장소를 선택해야 한다.

## 6. 백엔드 변경 방향

### 데이터 모델

`open_mats`에 좌표 필드를 추가한다.

MVP 필수:

- `latitude DECIMAL(10, 7)` nullable
- `longitude DECIMAL(10, 7)` nullable

후속 검토:

- `map_provider VARCHAR(30)`
- `map_place_id VARCHAR(100)`
- `geocoded_at TIMESTAMP(6)`
- `geocode_status VARCHAR(30)`

### 요청 DTO

`OpenMatCreateRequest`, `OpenMatUpdateRequest`에 추가:

```json
{
  "latitude": 37.5012345,
  "longitude": 127.0398765
}
```

프론트는 사용자가 카카오 검색 결과를 선택한 뒤 `locationName`, `address`, `latitude`, `longitude`를 함께 보낸다.

### 응답 DTO

`OpenMatResponse`에 추가:

```json
{
  "latitude": 37.5012345,
  "longitude": 127.0398765
}
```

### 검증

- `latitude`는 -90부터 90 사이여야 한다.
- `longitude`는 -180부터 180 사이여야 한다.
- 기존 데이터 호환을 위해 좌표는 nullable로 시작한다.
- 서버는 MVP에서 주소 기반 geocoding을 직접 수행하지 않는다.

## 7. 프론트엔드 변경 방향

### Flutter 앱

- 오픈매트 생성 화면에 장소명 또는 주소 검색 입력창을 추가한다.
- 카카오 장소/주소 검색 결과 후보 목록을 표시한다.
- 사용자가 후보 중 실제 장소를 선택할 수 있게 한다.
- 선택한 후보의 장소명, 주소, 위도, 경도를 저장 요청에 포함한다.
- 선택 후 지도 미리보기를 표시한다.
- 검색 결과가 없으면 주소나 장소명을 수정하도록 안내한다.
- 오픈매트 수정 화면에서도 동일한 장소 선택 흐름을 제공한다.
- 오픈매트 상세 화면에서 저장된 위도/경도로 카카오맵 WebView 지도 미리보기를 표시한다.
- 좌표가 없으면 기존 장소명/주소만 표시한다.
- `지도에서 보기` 버튼을 추가한다.
- 카카오맵 앱이 없을 때 카카오맵 웹 fallback이 동작하도록 한다.

### React 관리자 웹

React 관리자 웹은 운영자 전용이다. 사용자 공유 흐름에는 포함하지 않는다.

관리자 기능으로는 후속 또는 선택적으로 아래를 검토한다.

- 오픈매트 관리 상세에서 좌표 유무 표시
- 운영자가 오픈매트 장소를 검색하고 좌표를 보정하는 UI

## 8. 지도 연동 참고

MVP 지도 provider는 카카오맵으로 확정한다.

카카오맵 적용 원칙:

- 생성/수정 화면의 장소 검색은 카카오 Local API 또는 카카오 지도 검색 API를 사용한다.
- 카카오 검색 결과의 `x`는 경도(`longitude`), `y`는 위도(`latitude`)로 저장한다.
- 상세 화면 지도 미리보기는 저장된 위도/경도를 사용해 카카오맵을 WebView로 표시한다.
- `지도에서 보기`는 카카오맵 앱 딥링크를 우선 시도하고, 앱이 없으면 카카오맵 웹 URL로 fallback한다.

공통 원칙:

- 상세 화면은 저장된 좌표를 사용한다.
- 매번 상세 조회 때 주소를 좌표로 변환하지 않는다.
- 좌표 검색은 생성/수정 시점에 사용자가 후보를 선택하는 방식으로 처리한다.
- Flutter 네이티브 지도 SDK 대신 WebView 기반 카카오맵 미리보기를 우선 적용한다.
