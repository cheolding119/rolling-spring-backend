# k6 Stress Test Plan

## 목적

- 어떤 API가 먼저 느려지는지 확인
- 어떤 API가 먼저 실패하는지 확인
- DB, CPU, 메모리 중 무엇이 먼저 흔들리는지 확인
- 운영 전 우선 튜닝 대상을 정리

## 핵심 모니터링

1. `HTTP Status Codes`
2. `HTTP P95 Latency`
3. `HTTP Request Rate`
4. `Hikari Connections`
5. `Hikari Pool Usage %`
6. `CPU Usage %`
7. `JVM Heap Usage %`
8. `GC Pause Avg (5m)`

## 공통 사전 체크

- [ ] Spring이 실행 중이다
- [ ] `local` 또는 테스트용 프로필이 맞다
- [ ] DB가 연결되어 있다
- [ ] Prometheus, Grafana가 실행 중이다
- [ ] 테스트 데이터가 충분하다
- [ ] 인증이 필요한 API는 테스트 사용자 준비가 끝났다
- [ ] 신청 테스트용 오픈매트는 `RECRUITING` 상태다

## 공통 판정 기준

통과:

- [ ] `5xx` 가 없다
- [ ] `p95` 가 급격히 무너지지 않는다
- [ ] Hikari pending이 계속 쌓이지 않는다
- [ ] CPU, heap, GC가 비정상적으로 치솟지 않는다
- [ ] 부하 종료 후 회복된다

실패:

- [ ] `5xx` 가 발생한다
- [ ] `p95` 가 급격히 상승한다
- [ ] Hikari pending이 발생하고 유지된다
- [ ] CPU가 계속 높게 유지된다
- [ ] Heap Usage % 가 계속 우상향한다
- [ ] 부하 종료 후에도 회복되지 않는다
